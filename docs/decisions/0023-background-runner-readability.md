# ADR-0023: 실행 플래그를 없애고 작업 조회·검증을 분리해요

- 상태: 확정
- 작성·확정일: 2026-10-30
- 확정 근거: 사용자가 `BACKGROUND_JOBS_ENABLED` 제거와 SQL·설정 검증·실패 처리의 가독성 개선을 요청했어요.
- 관련 기록: [ADR-0022](0022-d1-scheduled-jobs.md)를 대체해요. D1 대기열·실행권·복구·재시도 규칙은 유지하고,
  실행 플래그와 실행기 내부 코드 배치만 바꿔요. [ADR-0003](0003-shared-modules-sync-async.md)의 기능별 모듈 규칙을 적용해요.
- 구현·검증 상태: 기존 #10 worktree에서 코드·설정·생성 타입·검사를 수정했어요. 로컬 검사 결과는 아래에 남겨요.
  커밋·원격 배포·실제 공급자 검증은 이번 변경 범위에 포함하지 않아요.

## 문제와 현재 상태

예약 실행이 들어와도 기본값이 false인 플래그 때문에 접수된 작업을 처리하지 않았어요.
`runner.ts`에는 실행 순서, SQL, JSON 형태 확인, 생성 설정 비교, 오류 분류가 섞여 있었어요.
사용자는 플래그 제거를 요청하고 긴 조건문과 `failAnalysis` 인자의 가독성을 지적했어요.

## 결정

- 실행 플래그와 Wrangler 변수·생성 타입·테스트의 활성화용 환경 복사를 없애요.
  scheduled 핸들러는 대기열을 확인하고 실행 가능한 작업을 처리해요. 빈 대기열은 공급자를 호출하지 않아요.
- `getAnalysisJob`·`getDeliveryMessage`를 기존 작업 모듈에 두어요.
  실행기는 이름 있는 조회 함수를 호출하고, SQL과 바인딩은 해당 작업의 저장 코드와 함께 관리해요.
- `parseGenerationProfile`은 기존 Zod 설정 스키마로 형태와 모델을 검증한 뒤 현재 프로필과 생성 키를 확인해요.
  긴 boolean 조건을 순서가 드러나는 검사로 나누고, 지원하지 않는 설정은 공급자 호출 전에 거부해요.
- `generationFailure`에서 실패 코드와 사용량을 함께 반환해요. timeout·unknown·temporary와 예상하지 못한 오류는
  기존처럼 결과 불명으로 남겨요. 알려진 오류의 사용량을 보존하고 알 수 없는 사용량을 0으로 만들지 않아요.

## 근거와 대안

2026-10-30 확인한 [D1 prepared statement 문서](https://developers.cloudflare.com/d1/worker-api/prepared-statements/)는
SQL에 값을 바인딩하는 API를 제공해요. 현재 `statement`도 `prepare().bind()`를 사용해요.
SQL 자체를 바꿀 필요보다 실행 흐름과 저장 코드를 분리할 필요가 크다고 판단했어요.
ORM은 쿼리 타입 검사에 유리할 수 있지만, 이번 조회 두 곳을 정리하려고 의존성과 기존 batch 전이를 교체하지는 않아요.

실행 플래그는 배포 후 일괄 중지 수단이지만, 현재는 요청한 기능을 기본 설정에서 멈추게 해요.
사용자의 제거 요청을 적용하고 다른 이름의 중지 플래그를 추가하지 않아요.
설정 검증을 없애면 기존 설정으로 접수한 작업이 달라진 프롬프트나 모델로 실행될 수 있어 검증은 유지해요.
오류 분류도 삭제하면 SDK 내부 호출 결과가 불명확한 요청을 다시 실행할 수 있어 기존 정책을 유지해요.

## 가정·한계와 영향

이 코드를 배포하면 Cron은 별도 활성화 설정 없이 대기 작업을 처리해요. 이번 작업에서는 배포하지 않아요.
Google 프로젝트 전체의 RPM·TPM·RPD를 집행하는 변경은 아니며 실제 공급자 성공과 사용량 정책은 #5·#7에 남아요.
SQL·스키마·저장 JSON 형식·생성 키·프롬프트·모델·SDK 재시도·호출 제한 시간은 바꾸지 않아요.
추가 데이터 마이그레이션이나 Android 변경은 없어요.

## 검증과 재검토 조건

플래그 없는 환경으로 실행하는 검사를 먼저 바꾸고, 기존 코드가 작업을 queued에 남겨 실패하는 것을 확인했어요.
기존 scheduled → 메타데이터·Gemini SDK → D1 저장 검사는 기본 환경으로 실행하도록 수정했어요.
모델 누락·타입 오류·지원하지 않는 모델·프로필 변경·키 불일치는 공급자 호출 전에 실패해야 해요.
오류별 실패 코드·사용량 보존과 예상하지 못한 오류의 재호출 차단도 확인해요.

2026-10-30 기존 #10 worktree에서 아래 검사를 통과했어요.

- 작업·migration 검사 49개를 통과했어요. 기존 40개에 설정 불일치 7개와 예상하지 못한 오류 2개를 추가했어요.
- `ANDROID_HOME=/Users/ted/Library/Android/sdk mise run check`가 통과했어요.
  workerd 169개·API 도구 16개·공통 도구 49개와 타입·포맷·Worker dry-run을 확인했어요.
  Android 포맷·Lint·단위 테스트·debug 빌드와 Terraform backend 없는 검증도 통과했어요.
- `git diff --check`, 수정 전 작업 트리와의 diff, 변경 문서의 상대 링크를 확인했어요.
  기준 커밋은 `37fea11021e4472c38c7bbe8a0811f26b8406c09`이며 변경은 미커밋 상태예요.

공급자 응답은 fixture이며 원격 실행의 증거로 쓰지 않아요.
쿼리와 타입 불일치가 실제 유지보수 문제로 반복되면 타입을 검사하는 쿼리 도구를 별도로 비교해요.

## 반론과 변경 이력

- 2026-10-30: 실행을 막는 플래그와 실행기 가독성에 대한 사용자 지적을 반영했어요.
  SQL은 기존 바인딩 방식을 유지하고, 실행 순서에서 조회·검증·오류 분류를 분리했어요.
