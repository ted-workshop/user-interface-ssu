# ADR-NNNN: 결정 또는 제안 제목

- 상태: 제안 / 확정 / 기각 / 대체 중 하나
- 작성일: YYYY-MM-DD
- 확정·기각일과 근거: 사용자 승인 또는 승인 범위 안의 자율 판단을 적어요. 제안 단계면 미확정이에요.
- 관련 기록: 선행 기록, 대체하는 기록, 대체한 기록을 연결해요. 없으면 없다고 적어요.
- 구현·검증 상태: 문서 검토, 구현, 로컬 검사, 배포, 공급자·실제 사용 검증을 각각 적어요.

## 문제와 현재 상태

해결할 문제, 사용자에게 보이는 결과, 제약과 관련 코드·명세를 적어요.
기존 결정을 따르거나 바꾸는 지점도 연결해요.

## 결정 또는 제안

선택한 내용과 같은 문제에 속한 세부 판단을 적어요. 적용할 범위와 아직 정하지 않은 부분을 구분해요.

## 근거와 대안

확인한 사실과 출처, 그 사실에서 도출한 판단을 구분해요.
대안의 장점·비용·한계, 채택하지 않은 이유, 선택한 안이 현재 요구에 맞는 이유를 적어요.
외부 자료에는 URL·확인 날짜를, 실측에는 버전·환경·재현 명령과 결과를 붙여요.

## 가정·한계와 영향

아직 확인하지 않은 내용과 선택으로 감수하는 비용·위험을 적어요.
바뀌는 API·데이터·호출부와 필요한 마이그레이션·복구 방법이 있으면 적어요.

## 검증과 재검토 조건

무엇을 어떻게 확인할지, 실제로 확인한 결과, 미실행 항목과 이유를 구분해요.
어떤 측정값·요구 변경·반례가 나오면 판단을 바꿀지 적어요.

## 반론과 변경 이력

- YYYY-MM-DD: 반론, 답변과 추가 근거, 채택·기각·미해결 결과를 적어요.
- YYYY-MM-DD: 상태·출처·검증 결과를 갱신한 이유를 적어요.
