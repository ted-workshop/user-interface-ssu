# ADR-0039: Android 코드를 기능별 패키지로 나눠요

- 상태: 제안
- 작성일: 2026-11-16
- 확정·기각일과 근거: 미확정이에요. Android 담당 세 명(#27·#28·#29)의 PR 리뷰 의견을 받아 정해요.
- 관련 기록: 없음.
- 구현·검증 상태: 문서 제안만 있어요. 코드는 옮기지 않았고 Android 검사는 실행하지 않았어요.

## 문제와 현재 상태

Android 앱 코드는 모두 `kr.ac.ssu.qletter` 한 패키지에 있어요.
공통 기반 PR #50과 모음 화면(#60) 브랜치만으로도 같은 패키지에 10개가 넘는 클래스가 생겨요.
범위 이슈 #27·#28·#29의 화면을 모두 만들면 40~50개 파일이 한곳에 쌓일 것으로 예상해요.
그러면 파일을 찾기 어렵고, 어느 범위의 코드인지 경로만으로 알 수 없어요.

## 제안

패키지를 기능 단위로 한 단계 나눠요. 범위 이슈와 담당이 경로에 그대로 드러나요.

```text
kr.ac.ssu.qletter
├── common/      MainActivity, QletterApplication, QletterApi, Session, SessionStore, TabFragment
├── account/     로그인·회원가입·비밀번호 찾기·계정 설정 (#27)
├── channel/     채널 (#27)
├── home/        홈 (#28)
├── summary/     영상 요약 (#28)
├── report/      리포트 목록·상세 (#28)
└── collection/  모음·모음에 담기·리포트 댓글 (#29)
```

- 다른 패키지에서 쓰는 클래스와 메서드만 `public`으로 열어요.
- 옮기는 순서
  1. PR #50이 머지된 뒤 공통 파일을 `common/`으로 옮기는 PR을 따로 올려요. 파일 이동만 담아요.
     - `MainActivity`는 main·debug 매니페스트에, `QletterApplication`은 main 매니페스트에 등록돼 있어 두 매니페스트를 함께 고쳐요.
     - `FoundationTest`는 `SessionStore` 생성자와 `snapshot()`을 같은 패키지에서 써요. 테스트도 `common/`으로 함께 옮겨 세션 내부 API를 `public`으로 열지 않아요.
  2. 각 담당자는 자기 기능 패키지를 자기 구현 PR에서 만들어요. 모음 화면은 #60 PR에서 `collection/`으로 옮겨요.
  3. Android Studio의 **Refactor → Move**로 옮겨 import와 `AndroidManifest.xml`의 Activity 경로를 함께 바꿔요.
- 패키지 이름은 리뷰에서 바꿀 수 있어요.

## 근거와 대안

- 이 앱은 화면 단위로 담당이 나뉘어 있고(#26), 화면 하나를 만들 때 Activity·Fragment·Adapter·데이터 클래스를 함께 고쳐요.
  기능별로 모으면 고칠 파일이 한 폴더에 있고, 담당자끼리 같은 폴더를 덜 고쳐 충돌도 줄어요.
- 한 패키지에 계속 두면 옮기는 작업은 없지만, 파일이 늘수록 찾기 어려워 채택하지 않았어요.
- `activity/`·`adapter/`·`model/`처럼 종류별로 나누면 화면 하나를 고칠 때 여러 폴더를 오가야 하고 세 담당자가 같은 폴더를 함께 고쳐 채택하지 않았어요.
- 기능 안을 `ui/`·`data/`로 한 번 더 나누는 구조는 기능당 파일이 10개 안팎인 지금은 필요하지 않아요.
  [AGENTS.md](../../AGENTS.md)의 "추측에 기반한 구조를 추가하지 않는다"는 원칙에 따라 지금은 한 단계만 나눠요.

## 가정·한계와 영향

- 40~50개는 범위 이슈의 화면 목록으로 추정한 값이에요. 측정값이 아니에요.
- PR #50이 머지되기 전에 옮기면 같은 파일에서 충돌하므로 이동은 #50 머지 뒤에 해요.
- 이동 뒤 진행 중인 브랜치에 `main`을 합치면 import 경로 충돌이 날 수 있어요.
- 앱 동작, 서버·DB·API 계약에는 영향이 없어요.

## 검증과 재검토 조건

- 문서 변경만 있어 `git diff --check`와 링크를 확인했어요. Android 검사는 실행하지 않았어요.
- 이동 PR에서는 다음을 확인해요.
  - `mise run android:check`와 `:app:assembleDebugAndroidTest`로 앱과 테스트 APK 빌드
  - 에뮬레이터에서 debug·release 홈 진입, debug 앱 아이콘의 '개발 서버 연결' 바로가기, 탭 전환과 세션 복원
- 한 기능 패키지의 파일이 너무 많아져 찾기 어려우면 그 기능만 안을 다시 나누고 이 기록을 갱신해요.
- 팀이 범위 분담을 바꾸면 패키지 이름도 다시 정해요.

## 반론과 변경 이력

- 2026-11-16: 기능별 한 단계 구조를 제안했어요.
- 2026-11-16: #28 담당 리뷰에서 `home`·`summary`·`report` 이름과 이동 순서에 동의했어요.
  #50 코드 기준으로 매니페스트 두 곳 갱신, `FoundationTest` 동반 이동, 테스트 APK 빌드와 기기 확인 항목을 더하자는 의견을 받아 옮기는 순서와 검증 조건에 반영했어요.
