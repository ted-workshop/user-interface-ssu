# ADR-0044: 리포트 탭에서 보관함·본문·모음을 연결해요

- 상태: 확정
- 작성일: 2026-11-21
- 확정 근거: 사용자가 담당 범위에서 가능한 작업을 찾아 실행하도록 요청했어요. #28 담당 범위의 자율 구현 판단이에요.
- 관련 기록: [ADR-0038](0038-android-foundation.md), [ADR-0039](0039-android-feature-packages.md), [ADR-0026](0026-report-read-http.md), [API 계약](../api-contract.md).
- 구현·검증 상태: 구현·로컬 형식/lint·단위 테스트·debug/release/기기 테스트 APK 빌드를 통과했어요. 기기 시나리오·스크린샷은 미검증이며 Draft로 검토해요. 운영 서버·실제 공급자 호출은 하지 않았어요.

## 문제와 현재 상태

main `59c23ba`에서 하단 리포트 탭은 제목만 보여요. #12의 조회 API와 #60의 모음 관리 화면은 병합됐지만 앱에서 이어지지 않아요.
[#28](https://github.com/ted-workshop/user-interface-ssu/issues/28)의 하위 작업 [#72](https://github.com/ted-workshop/user-interface-ssu/issues/72)로 목록·상세를 연결해 저장한 리포트를 읽고, #29 담당의 화면에는 진입점만 제공해요.

## 결정

- `report/` 기능 패키지에 리포트 탭·목록·상세와 조회 코드를 둬요. 기존 `collection/` 코드는 수정하지 않아요.
- 하단 리포트 안에 `내 리포트 | 모음`을 두고 이미 병합된 `CollectionsFragment`를 연결해요. 미구현인 둘러보기·공개 기능은 버튼을 만들지 않아요.
- 목록은 제목 검색, 생성 경로·발송 상태, 저장된 정확한 채널 URL 필터를 지원해요. 채널은 목록의 `채널만 보기`에서 선택하며 초기화로 해제해요.
- 한 번에 20개를 읽고 `nextCursor`가 있을 때 `더 보기`로 이어 받아요. 다음 페이지에도 같은 조건을 보내고, 실패하면 기존 목록을 유지한 채 그 페이지를 재시도해요.
- 기본 빈 보관함과 조건에 맞는 결과 없음을 나눠 안내해요. 원본 목업의 제목·채널 통합 검색은 서버 계약이 제목 검색만 제공하므로 `제목으로 찾기`로 표기해요. 총개수와 영상 길이는 API가 주지 않아 만들지 않아요.
- 목록의 ViewModel이 요청·받은 페이지를 보관해 회전·상세 왕복에 중복 조회나 목록 소실을 줄여요. 쿼리 조건만 saved state에 넣고 개인 본문은 디스크에 저장하지 않아요.
- 상세도 자식 Fragment로 열어 하단 탭을 유지해요. 기본 뒤로 가기는 원래 목록으로 돌아와요. 다른 하단 탭으로 이동하면 기존 공통 탐색 정책대로 리포트 화면을 폐기해요.
- 계정 변경·만료 시 공통 세션과 요청 세대를 대조해 이전 결과를 버려요. 본문에는 AI 작성과 시간 링크 미검증 안내를 표시해요.
- Markwon core 4.6.2로 Markdown을 네이티브 TextView에 표시해요. HTML·이미지 플러그인과 WebView를 사용하지 않아요. 링크는 자격증명 없는 HTTPS만 외부 앱으로 열고 원본 영상 주소는 검증한 videoId로 구성해요.

## 근거와 대안

- API 계약과 실제 `reports.ts`는 개인 권한, 제목 검색, AND 필터와 savedAt 순서 cursor를 제공해요. 별도 서버 변경이나 새 분석 요청이 필요하지 않아요.
- Markwon의 [설정 문서](https://noties.io/Markwon/docs/v4/core/configuration.html)·[플러그인 문서](https://noties.io/Markwon/docs/v4/core/plugins.html)를 2026-11-21 확인했어요. 링크 처리기를 지정할 수 있고 이미지 로더를 등록하지 않으면 외부 이미지를 내려받지 않아요. core의 Markdown 처리를 재사용해 직접 파서를 만드는 비용을 피했어요.
- 원문 Markdown만 표시하면 의존성은 줄지만 제목·강조·시간 링크를 읽기 어려워요. WebView는 HTML·스크립트·탐색 정책과 별도 생명주기 관리가 필요해 채택하지 않았어요.
- 상세 Activity는 독립 실행이 쉽지만 하단 탭을 유지하려면 별도 탐색 기반이 필요해 자식 Fragment를 사용해요.

## 가정·한계와 영향

- #28 전체(홈·영상 요약)는 이 변경으로 끝나지 않아요. #27 로그인 화면, #29의 모음에 담기·댓글은 각 담당자가 연결해요.
- 상세의 공개·댓글·모음에 담기와 모음 상세에서 리포트로 이동하는 기능은 이번 변경에 넣지 않아요. 상세 진입 계약은 `ReportDetailFragment.create(reportId)`예요.
- 목차·썸네일·본문 표 확장 등 디자인 완성 작업은 후속이에요. 본문 자체·원본 링크·빈 상태·조회 실패 복구를 먼저 연결해요. 원본 목업 이미지는 #28에 있는 화면을 기준으로 확인했어요.
- 목록의 보관 날짜는 UTC임을 표시해 기기 시간대의 날짜로 오해하지 않게 해요. 발송됨은 SMTP 접수라는 서버 의미를 유지해요.
- API·DB·운영 설정에는 변경이 없어요. Markwon core와 기존 lifecycle-viewmodel의 release 사용만 Android 의존성에 반영해요. Gradle 버전 카탈로그로 관리하며 Bun 의존성에는 영향이 없어요.

## 검증과 재검토 조건

- `ReportQueryTest`: 페이지별 검색·필터 유지, 조건 없는 쿼리, 위험한 링크 거부, 원본 영상 ID 확인.
- `ReportFlowTest`: 로컬 전용 debug 주소와 MockWebServer로 목록·다음 페이지·회전·상세 왕복·빈 상태·실패 재시도·모음 진입·404·로그아웃 중 늦은 응답을 검사해요. 외부 공급자 성공의 증거가 아니에요.
- 기기 테스트는 `-Pqletter.apiBaseUrl=http://127.0.0.1:3000/`로 빌드했을 때만 실행해요. 이 주소는 테스트가 기기 안에 띄우는 HTTP 서버예요. 기본 앱 주소와 운영 주소에서 테스트 계정 작업을 하지 않아요.
- 실제 검사 결과와 스크린샷은 아래 검증 이력과 PR에 기록해요. 형식·lint·단위 검사·앱 빌드와 기기 실행을 분리해요.
- 큰 본문에서 읽기 지연이 생기거나 표·목차가 필수 시연 범위가 되면 렌더링 구성을 확장해요. 다른 하단 탭에 다녀와도 필터·스크롤을 유지해야 한다면 공통 탐색 정책을 다시 정해요.

## 반론과 변경 이력

- 2026-11-21: #28 담당 범위에서 기존 API와 #29 화면을 연결하는 결정을 기록했어요. ADR-0040은 PR #71에서 사용 중이므로 번호를 분리했어요.

- 2026-11-22: main의 ADR-0041(Gemini 503)과 번호가 겹쳐 이 기록을 ADR-0044로 옮겼어요. PR #81의 ADR-0042·0043은 해당 담당자의 기록으로 유지해요. 결정 내용과 최초 작성일은 바꾸지 않으며, 예전 번호와 파일은 PR #73의 이전 커밋에서 확인할 수 있어요. 목차의 리포트 행을 Android 공통 기반 옆으로 옮겨 최신 main의 기록 추가와 충돌하지 않게 했어요.

## 검증 이력

- 2026-11-21: JDK 25.0.5·Gradle 9.6.0·SDK 37.0에서 `spotlessCheck lintDebug testDebugUnitTest assembleDebug assembleRelease assembleDebugAndroidTest`를 통과했어요. `android:check`의 네 Gradle 작업을 모두 포함하고 release·기기 테스트 APK 빌드를 추가했어요. 단위 테스트는 기존 23개와 신규 4개, 총 27개가 통과했어요. 이 실행 환경의 프록시는 저장소 밖 Gradle 사용자 설정으로만 지정했어요.
- 신규 화면의 API 28 전용 접근성 속성을 AndroidX `ViewCompat`로 바꿨어요. 기존 공통·모음 코드 등의 lint 경고는 별개로 남아 있으며 이번 파일에는 lint 오류가 없어요.
- 이 환경에는 `/dev/kvm`이 없어 API 37 Pixel 7 x86_64 에뮬레이터를 소프트웨어 모드로 시도했지만 정상 부팅을 확인하지 못했어요. 따라서 기기 테스트 4개는 컴파일만 확인했고, 성공·스크린샷 증거로 표시하지 않아요.
- 기기 검증 전까지 #72 완료·Ready for review로 표시하지 않아요. 기기가 연결된 개발 환경에서 다음 명령으로 확인하고 실제 캡처를 PR에 첨부해요.

```sh
cd apps/android
mise exec -- ./gradlew -Pqletter.apiBaseUrl=http://127.0.0.1:3000/ :app:connectedDebugAndroidTest
adb pull /sdcard/Android/data/kr.ac.ssu.qletter.debug/files/report-check ./report-check
```

테스트가 기기 내부 MockWebServer와 임시 세션을 사용하므로 별도 API 서버·Gmail·YouTube 키는 필요 없어요. 캡처는 실제 앱 화면에 테스트 데이터를 표시한 결과라는 점을 함께 밝혀요.
