# ADR-0032: Gemini는 한 번만 호출하고 503은 사용자가 다시 시도하게 해요

- 상태: 확정
- 작성·확정일: 2026-11-07
- 확정 근거: 사용자가 2026-11-07에 SDK 자동 재시도를 끄고, 이미 요약한 영상의 재사용 원칙을 지키도록 생성 설정은 바꾸지 않기로 정했어요.
- 관련 기록: [ADR-0017](0017-report-generation-parity.md)의 "SDK 기본 동작" 중 재시도 부분과 [ADR-0023](0023-background-runner-readability.md)의 5xx 결과 불명 분류 일부를 대체해요. [ADR-0024](0024-direct-summary-http.md)의 하루 3회·사용자 재시도 정책은 그대로예요.
- 구현·검증 상태: 로컬 구현과 workerd 검사를 마쳤어요. 2026-11-07 로컬 CLI로 실제 생성 1건이 한 번의 요청으로 성공했어요. 배포는 확인하지 않았어요.

## 문제와 현재 상태

10월 30일부터 11월 3일까지 같은 설정의 요약이 Gemini `503 service_unavailable`로 계속 실패했어요([Gemini 기록](../gemini.md)).
`@google/genai` 2.31.0의 `interactions.create`는 기본으로 408·409·429·5XX에 최대 4번 더 보내요(0.5초부터 최대 8초 간격).
그래서 요약 1건이 HTTP 요청 최대 5번이 되고, 무료 플랜의 분당 5회·하루 20회 한도를 실패만으로 빠르게 써요.
마지막 응답이 5xx면 앞선 요청이 처리됐는지 알 수 없어 `provider_outcome_unknown`으로 남았고, 사용자는 다시 시도할 수 없었어요.

## 결정

- `interactions.create`에 `retries: { strategy: "none" }`을 넘겨 요약 1건마다 Gemini를 한 번만 호출해요.
- 한 번만 보낸 요청의 503은 처리되지 않은 요청이라 `temporary`로 저장해요. 기존 재시도 규칙대로 총 3시도 안에서 사용자가 다시 시도할 수 있어요.
- 500·502·504는 공급자가 처리하다 실패했을 수 있어 지금처럼 `provider_outcome_unknown`으로 남겨요. 시간 초과·알 수 없는 오류도 같아요.
- 생성 설정의 `sdkRetries: "default"`는 바꾸지 않아요. 재시도는 같은 요청을 다시 보낼지의 전송 정책이라 리포트 내용과 무관하고,
  값을 바꾸면 생성 키가 달라져 이미 요약한 영상을 다시 요약하게 돼요. 이 값은 기존 리포트 재사용을 위한 식별자로 남겨요.
- 재시도는 지금처럼 하루 3회 안에서 차감해요.

## 근거와 대안

- 사용량 초과는 429예요. 앱은 Cron 1분마다 분석 작업 하나만 실행하고, 다른 요청 없이 하나만 보낸 시험에서도 5회 모두 503이었어요.
  그래서 503의 원인을 우리 앱의 동시 사용량으로 보지 않고, 과부하 중 빠른 재시도가 한도만 쓴다고 판단했어요.
- 생성 설정을 `"none"`으로 바꾸는 대안은 동작과 값이 일치하지만, 이미 요약한 영상을 다시 요약하지 않는 원칙과 맞지 않아 채택하지 않았어요.
- 서버가 몇 분 뒤 자동으로 다시 시도하는 대안은 "사용자 요청 전에는 다시 호출하지 않는다"는 ADR-0024 정책을 바꿔야 해서 이번에는 하지 않아요.

## 가정·한계와 영향

- 503이 "처리되지 않음"이라는 판단은 HTTP 의미와 지금까지의 관찰에 근거해요. Gemini가 503 뒤 과금한 사례를 확인하지는 않았어요.
- 일시 장애가 길면 사용자가 3시도를 금방 쓸 수 있어요. 그때는 서버 자동 재시도나 다른 모델을 다시 검토해요.
- 같은 영상을 모델이 바뀌어도 재사용할지는 이 기록의 범위가 아니에요.

## 검증과 재검토 조건

- 2026-11-07 Windows 11 로컬에서 workerd 347개, Biome, 타입 검사를 통과했어요. 수정 전 코드로는 새 테스트 4개가 실패하는 것도 확인했어요.
  503·429에도 네트워크 호출이 1번인지, 503 뒤 사용자 재시도로 새로 생성되는지, 500·502·504는 재시도를 막는지를 다뤄요.
- 2026-11-07 WSL Ubuntu의 CLI로 `retry-check-1107a`를 실행해 `gemini-3.6-flash` 생성이 61초 만에 한 번의 요청으로 성공했어요([Gemini 기록](../gemini.md)).
  503 때 요청이 1번만 가는지는 실제로 관찰하지 못했어요.
