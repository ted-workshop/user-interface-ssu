# ADR-0043: 인증 게이트와 계정·채널 화면을 API 계약에 맞춰 연결해요

- 상태: 확정
- 작성·확정일: 2026-11-22
- 확정 근거: [#27](https://github.com/ted-workshop/user-interface-ssu/issues/27)의 승인된 화면 범위에서 자율적으로 정한 구현 판단이에요.
- 관련 기록: [ADR-0038](0038-android-foundation.md)의 세션 저장·탭 기반, [ADR-0039](0039-android-feature-packages.md)의 기능 패키지, [ADR-0042](0042-android-local-network-permission.md)의 debug 네트워크 권한, [API 계약](../api-contract.md)의 인증·채널·수신 설정을 따라요.
- 구현·검증 상태: 화면·API 연결과 단위·기기 검사를 구현했어요. 실제 메일 수신과 실제 YouTube 채널 조회는 키가 없어 미확인이고, 배포·실사용 검증은 남아 있어요.

## 문제와 현재 상태

#27은 로그인·회원가입·비밀번호 찾기·계정 설정·로그아웃과 채널 목록을 요구해요.
서버는 #9·#13에서 이메일 인증, 세션, 비밀번호 재설정, 수신 주소, 확인 주기, 채널 미리보기·등록·중지·삭제를 제공하지만
Android에는 인증 화면과 계정·채널 탭이 없었어요. 기존 공통 탭은 로그인하지 않아도 열려 있었고,
탭 내용은 자리 표시자였어요.

계약과 목업 사이에는 다음 차이가 있어요.

- 이메일 확인과 비밀번호 재설정은 링크가 아니라 앱에 입력할 코드를 보내요.
- 계정 닉네임을 바꾸는 API는 #7·#9 계약에 없어요.
- 확인 주기는 60·360·1,440분만 허용해요. 목업의 15분은 서버 선택지가 아니에요.
- 수신 주소와 확인 주기는 계정 화면 목업에 있지만 #27의 채널 포함 범위 문장에는 따로 적혀 있지 않아요.

## 결정

- 앱 진입점을 `AuthActivity`로 바꾸고, `MainActivity`는 세션이 있을 때만 열어요.
  로그아웃·만료·현재 세션의 401이면 `MainActivity`가 `AuthActivity`로 돌아가요.
  로그인 성공 뒤에는 `CLEAR_TASK`로 새 task를 시작해 이전 계정의 화면·back stack을 남기지 않아요.
- 로그인·회원가입·이메일 확인·비밀번호 찾기를 `AuthActivity`의 화면으로 두고,
  비밀번호는 다음 확인 화면까지 Activity 범위 `ViewModel`에만 보관해요. 토큰·비밀번호는 로그에 남기지 않아요.
- 로그인·가입·확인·재설정 요청은 화면 범위 `AuthRequestViewModel`이 소유해요. 화면 회전으로 View가 다시 만들어져도 요청과 결과가
  유지되고, 화면을 실제로 떠나 ViewModel이 정리될 때 요청을 취소해요.
- 수신 주소 확인 코드 창은 성공 응답이 Activity 상태 저장 뒤 도착하면 바로 `dismiss()`하지 않고 재개 때 닫아요.
  결과 ID는 Fragment Result에 먼저 남겨 부모가 목록을 다시 읽게 해요.
- 비밀번호 변경 뒤 로그인·회원가입 화면의 뒤로 가기는 `openedForPasswordChange`만 기준으로 삼아,
  이전에 열었던 `START_FORGOT` Intent가 남아 Activity를 닫는 일을 막아요.
- debug 개발 서버 연결 바로가기는 앱 launcher가 된 `AuthActivity`에 등록해요.
- 계정 탭은 `GET /v1/me`로 이메일·닉네임을 읽고 로그아웃을 제공해요.
  닉네임 변경은 API가 없어 읽기 전용으로 두고, 비밀번호 바꾸기는 서버가 지원하는 재설정 코드 흐름을 재사용해요.
- 계정 탭에서 수신 주소 목록·추가·확인 코드·재발송·삭제와 확인 주기를 제공해요.
  주소 추가 직후 확인 메일을 요청하고 코드 입력 창을 열어요. 확인 주기는 60·360·1,440분만 보여 줘요.
- 채널 탭은 미리보기 → 등록 → 목록 → 일시 중지/다시 시작 → 삭제를 제공해요.
  삭제 확인에는 기존 리포트가 보관함에 남고 자동 요약·발송만 멈춘다는 안내를 넣어요.
- 네트워크 응답이 Activity 상태 저장 뒤 도착하면 화면 전환·확인 코드 창을 pending으로 보관하고
  `onResume`에서 한 번만 적용해요. 삭제 확인창 결과에는 대상 ID를 담아 회전 뒤에도 같은 대상을 지워요.
- 오류는 입력 오류, 잘못된 로그인, 이메일 확인 필요, 네트워크 실패, 요청 제한, 서비스 일시 불가를
  서로 다른 문장으로 보여 줘요. 서버 오류 원문은 그대로 노출하지 않아요.
- 공개 인증 요청은 세션을 붙이지 않는 `QletterApi.newPublicCall`로 보내고, 개인 요청만 Bearer 세션을 붙여요.

## 근거와 대안

- 탭을 항상 보여 주고 로그인 화면을 덮는 대안은 로그아웃·401 뒤 이전 Fragment가 남거나
  늦은 응답이 새 계정 화면에 닿을 위험이 커서 채택하지 않았어요. ADR-0038의 “인증 화면은 결과만 넘긴다”는 경계와도 맞지 않아요.
- 화면마다 별도 Activity를 두는 대안은 공통 세션·뒤로 가기·권한 요청 진입점이 늘어나서 채택하지 않았어요.
- 닉네임 변경을 위해 `PATCH /v1/me`를 새로 만드는 대안은 #9의 완료된 서버 인증 범위를 넘고
  API·계약·검사 변경을 한 PR에 섞으므로 이번 범위에서 제외했어요. 필요하면 별도 API 작업으로 다뤄요.
- 현재 비밀번호를 입력받는 변경 화면은 서버에 해당 경로가 없어 만들지 않았어요.
  비밀번호 재설정 확인이 모든 세션을 폐기하므로 성공 뒤 로컬 세션도 지워요.
- 비밀번호 찾기 메일의 링크를 딥링크로 여는 대안은 서버가 코드를 보내고 앱 딥링크 계약이 없어 채택하지 않았어요.
- 수신 주소·확인 주기를 빼는 대안은 계정 목업과 이미 구현된 #13 API를 쓰지 못해 채택하지 않았어요.
- 채널 삭제를 즉시 지우는 대신 확인창을 두는 이유는 서버가 논리 삭제해도 사용자가 의도하지 않은 자동화 중단을 막기 위해서예요.

## 가정·한계와 영향

- 로컬 `.dev.vars`에 SMTP·YouTube 키가 없어 실제 확인 메일 수신과 실제 채널 미리보기·등록·중복 409를
  에뮬레이터에서 확인하지 못했어요. API workerd 검사와 화면 연결 코드로만 확인했어요.
- 채널 삭제 뒤 기존 리포트가 남는 것은 API의 논리 삭제 계약을 따르지만, 이번 수동 검증에는 리포트가 없어
  화면에서 직접 대조하지 못했어요.
- 닉네임 변경, 계정 이메일 변경, 소셜 로그인, 수신 주소 확인 코드 자동 입력은 이번 범위에 없어요.
- debug 앱은 ADR-0042에 따라 Android 17 로컬 네트워크 권한을 한 번 요청해요.
- #27의 하위 구현 이슈 #77·#78·#79·#80을 만들었어요. #27 본문·목업 갱신은 남아 있어요. 이 기록은 화면 구현 판단만 다뤄요.

## 검증과 재검토 조건

- `mise run android:check`: 통과. Spotless·lint·JVM 테스트·debug APK를 확인했어요.
- `:app:assembleRelease`: 통과. release APK에는 `ACCESS_LOCAL_NETWORK`가 없고 debug에만 있어요.
- `:app:connectedDebugAndroidTest`: Pixel 7 AVD(Android 17, API 37)에서 13개 통과.
  로그인 화면 표시, 탭 선택·회전 복원, 세션 저장·복원·만료,
  상태 저장 뒤 화면 전환·확인 코드 창이 재개 때 한 번 열리는지, 확인 성공이 상태 저장 뒤면 재개 때 닫히는지,
  삭제 확인창의 대상 ID가 회전 뒤에도 유지되는지, 비밀번호 변경 뒤 회원가입의 뒤로 가기가 로그인으로 돌아오는지를 확인했어요.
- debug APK를 설치한 뒤 `cmd shortcut get-shortcuts`에서 `개발 서버 연결` 바로가기가
  `AuthActivity`에 등록된 것을 확인했어요.
- 가입·수신 주소 확인 중 홈 이동 뒤 성공 응답이 오는 경로는 Activity 상태 저장 뒤 전환 요청을 재현하는 기기 검사로 확인했어요.
  실제 SMTP·YouTube 키가 필요한 메일·채널 검증은 여전히 미확인이에요.
- 로컬 Worker와 Pixel 7 AVD에서 가입 202 → 확인 코드 204 → 로그인 201 → 앱 재실행 뒤 세션 유지,
  계정·수신 주소·확인 주기·채널 목록 조회, 주소 추가 201·확인 요청 202·확인 204·삭제 204,
  채널 일시 중지·재개·삭제 204와 DB tombstone, 로그아웃 204를 확인했어요.
- 잘못된 비밀번호 401, 이메일 확인 필요 403, 채널 미리보기 503, 서버 중단 시 네트워크 오류가
  서로 다른 문구로 표시되는 것을 확인했어요.
- 실제 SMTP·YouTube 키가 준비되면 메일 수신·채널 미리보기·등록·중복 409·삭제 뒤 리포트 보존을 다시 확인해요.
  닉네임 변경 요구가 생기면 별도 API 결정을 먼저 남겨요.

## 반론과 변경 이력

- 2026-11-22: 목업의 닉네임 변경을 읽기 전용으로 두고, 비밀번호 변경은 재설정 코드로, 확인 주기는 API 선택지로 구현했어요.
  #27 본문·목업 갱신은 후속으로 남겼어요.
- 2026-11-22: 리뷰에서 상태 저장 뒤 `commit()`과 회전 뒤 삭제 대상 소실을 지적받아,
  화면 전환·확인 코드 창을 pending으로 보관해 재개 때 적용하고 삭제 확인창 결과에 대상 ID를 담았어요.
  해당 생명주기 재현 검사를 추가하고, 삭제 확인창 회전 뒤 DELETE가 한 번만 나가는 것을 로컬 API로 확인했어요.
- 2026-11-22: 2차 리뷰에서 확인 코드 창의 `dismiss()` 상태 손실, 회전 중 인증 요청 취소,
  비밀번호 변경 뒤 남은 `START_FORGOT` Intent, debug 바로가기 위치를 지적받아 모두 반영했어요.
  인증 요청을 화면 ViewModel로 옮기고, 확인 성공은 재개 때 닫으며, 바로가기를 `AuthActivity`로 옮겼어요.
