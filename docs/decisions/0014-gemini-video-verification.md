# ADR-0014: Agentic Video로 YouTube 영상을 요약하고 실제 공급자 검증을 분리해요

- 상태: 대체
- 대체 기록: [ADR-0016](0016-generate-content-video-input.md). 2026-10-27 실제 영상 처리 결과에 따라 요청 경로를 변경했어요.
- 작성·확정일: 2026-10-27
- 확정 근거: #5의 공개 영상 처리·한국어 리포트·사용량 검증 요구와 승인된 범위 안의 구현 판단이에요.
- 관련 기록: [ADR-0001](0001-workers-d1-free-tier.md), [ADR-0003](0003-shared-modules-sync-async.md), [이슈 #5](https://github.com/ted-workshop/user-interface-ssu/issues/5)
- 운영 설정: GitHub Secret·모델 Variable과 수동 배포 전달은 [ADR-0015](0015-gemini-production-settings.md)의 추가 결정을 따라요.
- 구현·검증 상태: 공통 함수와 수동 검증 도구를 구현했어요. workerd에서 실제 SDK와 가짜 HTTP 응답을 연결한 검사를 통과했어요.
  초기 영상 요청 다섯 번은 HTTP 429였어요. 키 재입력 뒤 두 번은 HTTP 403이었고 무료 티어 사용 불가 안내를 확인했어요.
  한국어 리포트 생성·원본 대조·실제 할당량 확인은 미완료예요.
  사용자가 확인한 현재 사용량 초과로 추가 공급자 검증을 보류해요.
  제품 요약 API·영속 작업·Android 연동·배포는 이번 범위에 포함하지 않아요.

## 문제와 현재 상태

#5는 공개 영상이 한국어 리포트로 이어지는 실제 결과와 사용량·지원 제한을 요구해요.
[기능 명세 F-01·F-03](../qletter/02-functional-spec.md)은 영상 전체 요약과 원본 대조를 요구하고,
내용을 부풀리거나 확인하지 않은 시점에 시간 링크를 붙이지 않도록 해요.

## 결정

- [summary.ts](../../apps/api/src/summary.ts)에 YouTube URL을 `interactions.create`의 `processing: "agentic"` 입력으로 전달하고
  `store: false`로 한국어 리포트를 생성하는 공통 함수를 둬요.
  공식 SDK 2.31.0을 정확한 버전으로 고정하고 Bun lockfile도 함께 갱신해요.
- 사용할 모델을 검증 설정에 명시해요. API가 거절하면 다른 모델·일반 텍스트 요약으로 바꾸지 않아요.
  자동 재시도를 끄고, 기본 180초의 중단 신호와 출력 4,096토큰 상한을 사용해요. 이는 검증 도구의 상한이에요.
- 검증 키는 Git에서 제외한 개인 설정으로 읽어요.
  현재 사용량 초과는 사용자가 확인한 정보로 남기고, 회복 확인 전에는 추가 생성 요청을 하지 않아요.
- 영상 URL은 허용한 YouTube 호스트와 11자리 영상 ID로 확인하고 같은 `watch` URL로 정규화해요.
  시점·공유·재생목록 인자는 제거해 영상 전체를 요청해요.
- 직접 URL의 제목·채널은 YouTube oEmbed에서 읽고 조회 URL을 출처로 남겨요.
  oEmbed 성공을 공개 여부·길이·로그인 제한·Gemini 접근 성공의 증거로 해석하지 않아요.
- 프롬프트는 영상 내용에 맞는 분량과 Qletter의 목차·핵심 정리를 요구해요.
  생각 블록은 제거하고 괄호 속 시점을 자동 링크로 만들지 않아요.
  공급자가 만든 링크도 `timestampVerification: "unverified"`로 반환하고 원본 대조를 따로 수행해요.
- 완료 상태와 리포트 제목 구조가 없는 응답은 실패로 분류해요. 이 형식 검사가 사실성·한국어 품질·영상 접근을 보증하지는 않아요.
- 토큰 수는 공급자가 반환한 입력·출력·생각·도구·캐시·합계만 기록해요. 누락은 `null`로 남기고 사용량을 계산해 채우지 않아요.
  오류도 HTTP 상태·제한된 reason·알려진 사용량과 할당량 위반 항목만 남겨요. 키·프로젝트 식별자·오류 원문을 내보내지 않아요.
- [수동 명령](../../apps/api/tools/summary.ts)은 서버용 개인 설정을 읽고, 외부 요청 전에 기록 ID를 독점 확보해요.
  중단·동시 실행 때 같은 ID를 다시 분석하지 않아요. 결과는 Git에서 제외한 `0600` 파일에 저장해요.
  재검증은 이전 결과를 보존하고 새 ID로 명시적으로 시작해요.
- 공개 기록에는 Qletter의 코드·공식 출처·검증 결과를 남기고 개인 참고 환경의 식별 정보는 제외해요.

## 근거와 대안

2026-10-27에 아래 공식 문서와 설치한 SDK의 타입·구현을 확인했어요.

- [Google 영상 입력 문서](https://ai.google.dev/gemini-api/docs/video-understanding)는 공개 YouTube URL 입력과
  `gemini-3.6-flash`의 Agentic Video 지원을 설명해요. 별도 다운로드·자막 수집 서버 없이 URL을 직접 전달할 수 있어요.
  URL 입력은 preview이며 무료 플랜의 하루 영상 입력 길이 제한은 8시간이라고 안내해요. 이는 이 계정의 잔여량 측정이 아니에요.
- [공식 SDK](https://googleapis.github.io/js-genai/release_docs/index.html)의 Interactions 타입과 실제 요청을 검사했어요.
  이 SDK 경로는 `retries: { strategy: "none" }`을 받으며 `generateContent`의 별도 retry 옵션과 구분해요.
  SDK의 할당량 오류 위치인 `error.error.details`는 가짜 HTTP 429 응답으로 회귀 검사해요.
- [한도 문서](https://ai.google.dev/gemini-api/docs/rate-limits)는 RPM·TPM·RPD를 프로젝트별로 적용하고
  실제 한도는 AI Studio에서 확인하도록 안내해요. 토큰 응답만으로 잔여 할당량·과금액을 알 수 없어 `quota`·`cost`를 `null`로 남겨요.
- 영상 다운로드·자막 추출은 시점 대조의 별도 근거를 확보하는 데 도움이 될 수 있어요.
  이번에는 SDK의 네이티브 입력부터 검증하고, 실제 품질·접근 문제가 확인되면 이 비용과 운영 부담을 다시 비교해요.

## 가정·한계와 영향

정규화한 일반 URL·Shorts·종료 라이브 주소의 파싱은 검사했지만 실제 영상 유형별 처리는 확인하지 못했어요.
비공개·삭제·로그인 필요·진행 중인 생방송은 초기 지원 범위에서 제외해요. 오류 400·404나 oEmbed 실패만으로 그 원인을 단정하지 않아요.
모델이 만든 Markdown의 외부 링크·본문은 아직 제품 UI로 제공하지 않아요. 제품 렌더링 때 별도 링크·HTML 처리가 필요해요.

공급자 429는 확인했지만 응답에 구체적인 한도·위반 항목이 없고 AI Studio 로그인 세션도 없었어요.
교체한 키의 텍스트 요청에서는 사용량이 반환됐고, 최소 영상 입력에서도 429를 관찰했어요.
따라서 일일 한도 소진·순간 요청 제한·무료 플랜 사용 가능 여부 중 어느 원인인지 확정하지 않아요.
무료 플랜 전환·유료 과금·다른 모델 선택·새 키 등록은 이 검증 결과만으로 실행하지 않아요.
공통 함수 추가는 기존 HTTP 계약·DB·메일 동작을 바꾸지 않아요. 운영 Secret 전달은 ADR-0015의 추가 범위예요.

키 재입력 뒤 모델 메타데이터 조회는 성공했지만 실제 영상 생성 요청은 HTTP 403이었어요.
공급자 응답의 무료 티어 사용 불가 문구를 별도 진단에서 확인했어요. 이 결과로 이전 429의 원인까지 확정하지 않아요.
2026-10-27 [Google 공식 안내](https://ai.google.dev/gemini-api/docs/troubleshooting#gemini-api-free-tier-unavailability)는
무료 이용 자격을 프로젝트 단위로 평가하며 같은 프로젝트의 키 재발급으로 해결되지 않는다고 설명해요.
또한 메타데이터 조회 성공은 생성 요청의 이용 자격·과금 상태 확인이 아니라고 구분해요.
이 403 프로젝트를 계속 사용하려면 이용 자격을 확인해야 해요. 결제 계정 연결·유료 전환은 실행하지 않았어요.
사용자가 현재 선택한 키의 사용량 초과를 확인했다고 알려 추가 공급자 호출은 하지 않았어요.
잔여량·초기화 시각을 새로 측정한 결과는 아니에요.

## 검증과 재검토 조건

- workerd에서 URL 거부·출처·SDK의 영상 요청·완료/실패·타임아웃·무재시도·토큰 누락·할당량 정보 비공개 처리를 확인해요.
- Bun에서는 기록 ID 경합·중단된 시도 보존·설정 거부·실패 기록을 확인해요. 이것은 실제 Gemini 성공 증거가 아니에요.
- `mise run check`에서 API·Android 포맷/Lint/JVM 테스트/debug 빌드·Terraform의 backend 없는 초기화와 검증을 통과했어요.
  ADR-0015의 운영 설정 검사까지 포함해 workerd 78개·Bun 명령 16개·공통 도구 49개를 통과했어요. 원격 CI·기기 UI·배포 검증과 구분해요.
- 실제 표본·시간·실패 결과는 [Gemini 검증 가이드](../gemini.md)에 남겨요. 프로젝트의 생성 접근 제한이 해소되면 동일 표본부터 다시 실행해요.
- 생성한 리포트의 주장·숫자·각 시간 링크를 원본과 대조한 뒤에만 #5의 성공 기준을 체크해요.
  AI Studio의 모델별 실제 한도·현재 사용량을 함께 확인한 뒤 영상 길이·사용량 정책을 정해요.

실제 처리 성공률·시간 링크 정확도가 요구를 충족하지 못하거나 모델·preview API의 지원·과금이 바뀌면
모델과 입력 방식을 다시 비교해요. 영속 요약 요청과 제품 API는 후속 이슈 #7·#10의 결정에 연결해요.

## 반론과 변경 이력

- 2026-10-27: 공식 SDK의 영상 입력과 한국어 리포트 공통 함수를 #5의 검증 범위로 구현했어요.
  분량 강제·자동 시간 링크 보정을 제외하고 실제 공급자 검증과 가짜 응답 검사를 분리했어요.
- 2026-10-27: 기존 키의 영상 요청 세 번과 교체한 키의 리포트·최소 영상 요청에서 429를 확인했어요.
  같은 새 키의 텍스트 진단에서 입력·생각 토큰 사용량이 반환된 결과를 함께 남겨요. 영상 요약 성공·원본 대조와 이슈 완료는 미확인으로 남겨요.
- 2026-10-27: 키 재입력 뒤 HTTP 403과 무료 티어 사용 불가 안내를 확인했어요. 모델 메타데이터 조회 성공과 생성 접근 제한을 구분하고,
  무료 이용 자격에 관한 공식 안내와 새 실측을 추가했어요. 기존 429 기록과 구현 결정은 보존해요.
- 2026-10-27: 사용량 초과 안내는 사용자 확인 정보로 구분하고, 공급자 추가 호출 없이 회복 뒤의 재검증을 남겨요.

### 2026-10-27 공통 함수와 검증 도구의 가독성 정리

공개 함수를 먼저 배치하고 프롬프트·내부 스키마를 아래로 옮겨요. `generateReport`에서는 SDK 요청·응답 검증을 읽고,
오류 분류와 허용된 할당량 필드 선택은 `toSummaryError`에서 처리해요. 할당량 타입과 누락 값의 `null` 변환을
하나의 Zod 스키마에서 정의해 별도 타입 선언과 중첩 변환을 줄여요.

검증 CLI는 시도 기록 확보·결과 저장을 담당하고 `analyzeVideo`가 메타데이터 조회·생성·실패 결과를 반환해요.
반환 타입을 분기에서 추론해 중복 결과 타입을 없애요. 파일 저장 실패를 공급자 실패로 바꾸지 않고,
생성 실패 뒤에도 이미 조회한 제목·채널을 보존해요.

별도 공급자 클래스나 공통 실행 프레임워크를 추가하지 않고 각 파일의 내부 함수로 역할을 나눠요.
외부 함수·프롬프트·기록 형식은 유지하며, 잘못된 할당량 정보의 429 분류·비공개 처리와 누락 상한의 `null` 보존을
기존 검사에 보완해 정리 전후 같은 동작을 확인해요. 실제 공급자 호출은 추가하지 않아요.

보완한 workerd 71개·Bun 명령 16개는 정리 전후 모두 통과했어요. 최종 `mise run check`도
공통 도구 49개와 Android·Terraform 검사를 포함해 통과했어요.

### 2026-10-27 URL 입력 검증 간소화

`parseYouTubeUrl`은 표준 `URL.parse()`로 주소를 읽고 Zod 스키마로 허용한 필드를 검사해요.
주소별 영상 ID 추출은 `extractVideoId`의 순서대로 반환하는 분기로 분리해 중첩과 가변 변수를 없애요.
필드별 허용값을 한곳에서 읽도록 기존 Zod를 사용하며 별도 URL 파싱 라이브러리는 추가하지 않아요.

2026-10-27 [URL 표준](https://url.spec.whatwg.org/#dom-url-parse)과 설치된 Workers 타입을 확인하고
Bun 1.4.2에서 정상 주소 처리·잘못된 주소의 `null` 반환을 확인하고 workerd에서 입력 계약을 검사했어요.
앞뒤 공백 허용·중간 개행 거부·지원 경로·호스트 거부 사례를 보완한 workerd 78개와 Bun 명령 16개가
변경 전후 모두 통과했어요. 허용한 주소 형식과 오류·정규화 반환 계약은 유지해요.
최종 전체 검사도 공통 도구 49개와 Android·Terraform 검사를 포함해 통과했어요.
