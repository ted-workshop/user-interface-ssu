# ADR-0050: 리포트 상세에 모음에 담기·댓글을 붙이고 모음 상세를 리포트 탭 안 Fragment로 바꿔요

- 상태: 확정
- 작성일: 2026-11-24
- 확정 근거: #69·#70의 "리포트 상세가 나오면 연결" 범위와 #60 제외 범위(모음 상세에서 리포트 열기)를 잇는 구현 판단이에요. 위치는 피그마를 따랐고 PR 리뷰에서 #28 담당자와 다시 확인해요.
- 관련 기록: [ADR-0034](0034-report-comments.md), [ADR-0045](0045-android-add-to-collection-sheet.md), [ADR-0046](0046-android-report-library.md), [ADR-0048](0048-android-collection-detail.md)
- 구현·검증 상태: 구현, 로컬 검사, 에뮬레이터 기기 테스트를 했어요. 실제 서버와 A/B 두 계정 확인, TalkBack 확인은 남아 있어요.

## 문제와 현재 상태

- 모음에 담기 시트(#82)와 댓글 영역(#84)은 독립 부품으로 머지됐지만 리포트 상세(#73)에 붙지 않았어요.
- 모음 상세(#87)의 리포트 줄을 눌러도 아무 일이 없었어요. ADR-0046은 진입 계약을 `ReportDetailFragment.create(reportId)`로 남겼어요.
- 모음 상세는 리포트 탭 컨테이너가 없던 때 임시로 만든 Activity였어요. 피그마 60:88과 달리 하단 탭이 없고, 흰 배경에서 상태바 아이콘이 보이지 않았어요.
  #73으로 컨테이너가 생기면 Fragment로 바꾸기로 했어요.

## 결정 또는 제안

- 피그마 60:166처럼 `YouTube에서 보기` 옆에 `모음에 담기` 버튼을 둬요. 시트는 상세의 자식 FragmentManager로 열어요.
- 피그마 61:265처럼 본문 아래에 `ReportCommentsFragment`를 붙여요. 본문을 받은 뒤에만 붙여서, 상세를 읽을 수 없는 리포트에는 댓글 영역도 없어요.
- 로그인이 풀리거나 계정이 바뀌면 본문과 함께 댓글·시트도 닫아요.
- `CollectionDetailActivity`를 `CollectionDetailFragment`로 바꿔요. 모음 목록이 리포트 탭의 같은 자리에 `replace`와 백스택으로 열어서 하단 탭이 유지돼요(ADR-0046의 상세 방식과 같아요).
  Intent extra는 인자로, 확인창·시트 결과는 자식 FragmentManager로 받아요. 매니페스트의 Activity는 지워요.
- 뒤로 가면 모음 목록이 다시 만들어지면서 목록을 새로 받아요. 그래서 이름 변경·빼기·삭제를 Activity 결과(RESULT_OK)로 돌려주던 코드를 없애요. 모음을 지우면 상세가 백스택을 꺼내요.
- 모음 상세에서 리포트 줄을 누르면 같은 자리에 `ReportDetailFragment`를 열어요. 모음 상세의 ViewModel은 백스택에 남아 있어서, 돌아와도 목록을 다시 받지 않고 스크롤 위치도 그대로예요. 뒤로 버튼은 `← 모음 이름`으로 보여요.
- 상세의 시트가 저장에 성공하면 상세가 `COLLECTIONS_CHANGED` 결과를 같은 FragmentManager에 넘겨요. 모음 상세는 돌아와서 목록을 처음부터 다시 받고, 헤더 개수는 모음 목록 API에서 다시 맞춰요.

## 근거와 대안

- 모음 상세 Activity를 두고 그 위에 상세를 덮어 열기: 처음에 이렇게 만들었어요. 코드는 적지만 하단 탭이 없고 상태바 문제가 남아서, 미뤄 둔 Fragment 전환을 이번에 함께 했어요.
- 별도 `ReportDetailActivity`: Activity와 세션 처리 코드를 하나 더 만들어야 하고 하단 탭도 없어요.
- 모음 상세를 닫고 내 리포트 탭으로 보내기: 상세를 보고 모음으로 돌아올 수 없어 채택하지 않았어요.
- 시트 결과 뒤 목록만 다시 받기: 헤더 개수가 틀린 채로 남아요. 모음 하나만 조회하는 API가 없어 목록 API(최대 100개)에서 찾아요.

## 가정·한계와 영향

- 빼기 요청이 진행 중이면 그 응답이 개수를 줄이므로, 목록 API의 개수로는 맞추지 않아요(ADR-0048의 이중 감소 방지와 같은 이유).
- 모음이 100개를 넘으면 개수를 맞추지 못해요. 다음에 들어올 때 다시 받아요.
- 피그마의 `링크 복사`, `공개하기`, `모음: AI 공부, …` 줄은 이번 범위가 아니에요. 공개 기능은 #23 정책 변경으로 만들지 않아요.

## 검증과 재검토 조건

- `CollectionDetailFragmentTest`: 기존 더 보기·빼기·회전·이름 바꾸기 잠금 검사를 Fragment로 옮겼어요. 더해서 줄을 누르면 상세·댓글이 열리고, 상세를 연 채 회전해도 상세가 남고 댓글이 두 번 붙지 않고, 뒤로 가면 목록을 다시 받지 않고 돌아오는지,
  시트 결과로 돌아와서 목록·개수를 다시 받는지, 모음 탭에서 열면 하단 탭이 남고 뒤로 가면 모음 목록을 다시 받는지 확인해요.
  댓글 붙이기와 결과 넘기기를 각각 지우면 해당 테스트가 실패하는 것을 확인했어요.
- 글씨 크기 2.0에서 `모음에 담기`가 두 줄이 돼도 잘리지 않고 두 버튼 높이가 같아요(스크린샷 확인).
- 기존 `ReportFlowTest`, `ReportCommentsFragmentTest`, `AddToCollectionSheetTest`가 그대로 통과해요(API 37 에뮬레이터).
- 다른 하단 탭에 다녀와도 모음 상세를 유지해야 하면 공통 탐색 정책(ADR-0046)을 다시 정해요.
