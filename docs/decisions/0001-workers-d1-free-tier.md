# ADR-0001: Cloudflare Workers와 D1을 무료 플랜으로 시작해요

- 상태: 확정
- 작성·확정일: 2026-10-20
- 확정 근거: 사용자가 실행 환경으로 `Cloudflare Workers`를 선택하고,
  무료 플랜 운영을 요청한 뒤 `그럼 D1으로 가자`라고 DB 선택을 확정했어요.
- 관련 기록: [기록 원칙](README.md), [초기 개발 환경 설계](../qletter/06-development-setup-design.md)
- 구현·검증 상태: 공식 문서와 현재 코드 확인까지예요. Workers 전환·D1 연결·스키마 구현·
  로컬 동작 검사·배포·실제 공급자와 사용자 흐름 검증은 아직 하지 않았어요.

## 문제와 현재 상태

Qletter API를 구현하면서 계정·요약 요청·리포트·채널·수신 설정을 영구 저장할 DB가 필요해요.
[기능 명세](../qletter/02-functional-spec.md)는 사용자별 데이터 분리, 앱 재진입 시 요청 복원,
같은 영상의 중복 처리 방지, 메일 실패와 리포트 보존을 요구해요.

확인한 코드 기준은 `8245e24f0b74ac722c08dd3b594062f6a1f0b975`예요.
[app.ts](../../apps/api/src/app.ts)는 health·공통 오류 응답을 제공하고,
[server.ts](../../apps/api/src/server.ts)는 Bun으로 로컬 서버를 실행해요. DB와 제품 인증은 없어요.
이 기록은 다음 서버 단계의 선택이며 초기 연결이 제품 기능을 제공한다는 뜻은 아니에요.

## 결정

- 서버 실행 환경은 Cloudflare Workers, 영구 저장 DB는 D1을 사용해요.
- 무료 플랜을 전제로 구현해요. 무료 한도 안에서 처리할 사용량과 초과 시 동작을 설계하고 검증해요.
  유료 플랜 전환은 이 결정에 포함하지 않아요.
- DB 선택이 요약·메일·영상 수집의 공급자나 실행 방식을 확정하지는 않아요.
  백그라운드 처리에 대한 Workflows 선택은 [ADR-0002](0002-workflows-for-background-jobs.md)의 제안이에요.

## 확인한 사실과 대안

아래는 2026-10-20 공식 문서를 확인한 시점의 한도예요. 구현·운영 전에 다시 확인해요.

| 기준 | D1 Free | Neon Free |
| --- | --- | --- |
| 저장 공간 | DB당 500MB, 계정 전체 5GB | 프로젝트당 1GB |
| DB 사용량 | 하루 500만 행 읽기·10만 행 쓰기 | 프로젝트당 월 100 CU-hours, 월 전송량 5GB |
| 사용량 기준 | 쿼리가 읽고 쓰는 행 수를 계산해요. | 할당한 연산 자원과 켜져 있는 시간을 함께 계산해요. |
| 비활성 상태 | 별도 DB 실행 시간 예산을 관리하지 않아요. | 5분간 비활성 상태면 DB 실행을 중지하고 조회 시 다시 시작해요. |
| 무료 한도 소진 | 일일 읽기·쓰기 한도 소진 시 쿼리가 오류를 반환해요. | CU-hours·전송량 소진 시 다음 기간이나 업그레이드까지 DB 실행이 중지돼요. |

D1의 수치와 행 계산 기준은 [요금 문서](https://developers.cloudflare.com/d1/platform/pricing/),
DB당 용량은 [한도 문서](https://developers.cloudflare.com/d1/platform/limits/)에서 확인했어요.
읽기 행은 반환한 결과 수와 다를 수 있어요. 인덱스 없는 조회는 많은 행을 스캔할 수 있고,
인덱스를 갱신하는 쓰기도 사용량에 포함돼요.
Neon의 수치와 중지 조건은 [플랜 문서](https://neon.com/docs/introduction/plans)에서 확인했어요.

Neon도 유효한 대안이에요. PostgreSQL을 그대로 사용하고 다른 PostgreSQL 환경으로 이전하기 수월해요.
Workers 연동도 [공식 가이드](https://neon.com/docs/guides/cloudflare-workers)가 있어요.
Neon을 선택하면 무료 운영이 불가능하다거나, Cloudflare 통일이 언제나 최적이라는 판단은 하지 않아요.

## 선택한 이유

현재 명세에서 필요한 관계형 저장·조회는 D1으로 시작할 수 있다고 판단해요.
PostgreSQL 전용 기능이 필요한 요구는 현재 명세에서 확인하지 못했어요.
Workers에서 D1 binding으로 접근하면 별도 DB 서비스의 연결·자격 증명·실행 시간 예산 관리를 줄일 수 있어요.
[D1 binding 문서](https://developers.cloudflare.com/d1/worker-api/d1-database/)가 이 연결 방식을 설명해요.

채널 자동 확인 때문에 DB를 자주 조회할 가능성도 고려했어요.
Neon에서 잦은 조회가 절전 진입을 막으면 월 CU-hours 예산을 더 소모할 수 있어요.
공식 계산식으로 0.25 CU를 30일 내내 실행하면 `0.25 × 24 × 30 = 180 CU-hours`예요.
이 계산은 [Neon 플랜 문서](https://neon.com/docs/introduction/plans)의 실행 시간 기준을 적용한 예시이며,
Qletter의 예상 사용량이나 실측 결과가 아니에요. 실제 확인 주기와 트래픽은 아직 정하지 않았어요.

D1을 택한 이유는 현재 요구와 무료 운영 제약에서 관리할 항목을 줄이기 위해서예요.
실제 부하 비교로 D1이 더 빠르거나 저렴하다고 증명한 결정은 아니에요.

## 가정·한계와 영향

- 계정·텍스트 리포트 중심의 데이터와 효율적인 쿼리가 무료 한도 안에 들어간다는 가정은 아직 미검증이에요.
- D1은 SQLite 기반이에요. PostgreSQL의 SQL·확장 기능과 동일하다고 가정하지 않아요.
  한 DB가 쿼리를 순차 처리하는 특성도 있어 실제 쿼리·동시 요청을 검증해야 해요.
  [D1 한도 문서](https://developers.cloudflare.com/d1/platform/limits/)가 처리 특성을 설명해요.
- Workers의 무료 CPU 한도와 인증 경로, Gemini 할당량, 메일 공급자·발신 도메인은 별도로 확인해야 해요.
  이 DB 결정만으로 전체 서비스가 항상 무료라고 보장하지 않아요.
- 데이터 보관·삭제 정책, 사용량 상한, 채널 확인 주기, 재시도 횟수는 아직 정하지 않았어요.
  뒤의 구현 결정에서 근거와 함께 남겨요.

## 검증과 재검토 조건

구현 때 사용자별 접근 제어·중복 요청·요청 복원·메일 실패 후 리포트 보존을 검증해요.
대표 데이터를 넣고 주요 조회의 실행 시간, `rows_read`·`rows_written`, 저장 용량을 측정해요.
확인 주기와 요약·발송 상한을 정한 뒤 일일 사용량을 계산하고 한도 오류의 안내·복구를 확인해요.
인증 CPU·실제 Gemini·메일 검증은 DB 로컬 검사와 구분해요. 이 항목들은 현재 미검증이에요.

D1의 용량·행 사용량·실제 지연이 요구를 충족하지 못하거나 PostgreSQL 전용 기능이 필요해지면 재검토해요.
공급자의 무료 한도·정책이 바뀌거나 실제 측정에서 Neon의 이점이 확인돼도 비교를 다시 해요.
전환을 정한다면 데이터 내보내기·변환·복구와 소비자 변경을 새 결정에 포함해요.

## 반론과 변경 이력

- 2026-10-20: 사용자가 Neon을 쓰는 것이 비추천인지, Cloudflare로 통일하는 것이 최선인지 물었어요.
  Neon의 PostgreSQL 이점과 공식 Workers 연동을 인정하고, 무료 운영에서 실행 시간 예산의 차이를 설명했어요.
  사용자는 비교 후 D1을 선택했어요. Neon의 성능·비용이 열등하다는 실측 결론은 없어요.
- 2026-10-20: D1 선택을 확정으로 기록했어요. 구현·배포·실제 사용 검증은 미완료예요.
