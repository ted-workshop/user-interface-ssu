# ADR-0025: 인증 화면을 공통 앱 탐색과 분리해 연결해요

- 상태: 확정
- 작성·확정일: 2026-10-31
- 확정 근거: 승인된 #27의 첫 작업인 로그인·회원가입 화면 범위에서 판단했어요.
- 관련 기록: [ADR-0018](0018-api-contract-and-policies.md)의 인증 정책과 [API 계약](../api-contract.md)을 적용해요.
- 구현·검증 상태: 인증 화면·HTTP 클라이언트와 로컬 검사를 마쳤어요. 인증 서버 #9와 공통 앱 기반 #28은
  아직 연결되지 않았고 실제 기기 UI·메일·로그인 흐름과 배포는 미검증이에요.

## 문제와 현재 상태

`main`의 `2b84d23`에는 Android의 debug 서버 연결 화면만 있어요. #27의 로그인·회원가입은
확정한 HTTP 계약으로 준비할 수 있지만, #28 담당의 탭·로그인 상태 전달과 #9의 서버 구현은 없어요.
서버나 공통 앱 구조를 대신 구현하면 담당 범위가 겹쳐요.

## 결정

- 제품용 `AuthFragment`에 로그인·회원가입·비밀번호 재설정 요청과 이메일 확인 재발송을 모아요.
  가입 성공은 이메일 확인 안내이며 로그인이나 실제 메일 수신 성공으로 표시하지 않아요.
- 호스트가 `AuthApi`와 로그인 성공 콜백을 제공해요. 세션 토큰을 Intent·Bundle·저장 상태·로그에
  넣지 않고 메모리의 결과 객체로 전달해요. Keystore 저장·재실행 복원·탭 이동은 #28에서 연결해요.
- debug 연결 화면에 인증 화면 진입 버튼을 추가해 실제 API 주소로 요청할 수 있게 해요.
  debug 호스트의 로그인 성공 안내는 응답 확인 도구이며 제품 로그인 유지 기능이 아니에요.
  release의 `MainActivity`와 공통 탐색은 바꾸지 않아요.
- 기존 OkHttp·Moshi·ViewModel·LiveData를 main 의존성으로 사용해요. ViewModel은 요청 중
  중복 제출과 화면 회전으로 인한 재요청을 막고, 화면 해제 뒤 늦은 응답은 전달하지 않아요.
  인증 POST의 자동 재시도·redirect는 사용하지 않으며 실패 뒤 사용자가 다시 제출해요.
  429의 정수 초 `Retry-After`가 있으면 대기 시간을 안내해요. 제한 자체는 서버가 적용해요.
  확인 메일 재요청이 실패해도 확인 안내 화면을 유지해 가입 요청을 반복하지 않아요.
- 비밀번호는 자르거나 정규화하지 않고 확인 값은 서버에 보내지 않아요. 이메일은 ASCII 소문자,
  닉네임은 NFC와 code point 2~20자, 가입 비밀번호는 code point 15~128자 계약을 따라요.
  입력·잘못된 자격 증명·이메일 미확인·요청 제한·네트워크·서버 오류를 구분해요.
  비밀번호 입력은 화면 회전·이동·해제 시 지우고 View 저장 상태에 넣지 않아요.
- 목업의 흰 배경, 왼쪽 정렬 제목, 검정 원형 모서리 버튼을 유지해요. 시스템 sans-serif를 쓰고
  제목 28sp·본문 16sp·보조 14sp, 화면 여백 24dp와 스크롤을 적용해요.
  인증 범위 색상은 배경 `#FFFFFF`, 본문 `#101010`, 보조 `#616161`, 테두리 `#D6D6D6`,
  오류 `#B42318`, 안내 배경 `#F6F6F7`이에요. 공통 테마는 변경하지 않아요.
  debug 호스트는 API 24에서도 지원하는 AndroidX의 시스템 바 설정을 사용해요.
- 목업의 비밀번호 8자·닉네임 2~12자는 최신 계약과 달라 교체해요. 계약에 없는 약관 동의
  체크박스나 연결할 문서가 없는 링크는 추가하지 않아요.

## 근거와 대안

2026-10-31 #27·#28 이슈, 첨부 목업과 현재 Android 코드를 확인했어요.
기존 Material Views·OkHttp·Moshi를 쓰면 추가 라이브러리나 가짜 로그인 경로가 필요하지 않아요.
공통 기반이 끝날 때까지 기다리는 대안은 충돌 위험이 작지만 독립적인 화면·HTTP 계약 검증도 늦춰요.
전체 앱 진입·세션 저장까지 구현하는 대안은 실제 로그인 유지 검증에 유리하지만 #28의 범위를 침범해요.
호스트 콜백을 경계로 정해 화면과 네트워크의 관찰 가능한 동작부터 완성해요.

[Android ViewModel 문서](https://developer.android.com/topic/libraries/architecture/viewmodel)를
2026-10-31 확인했어요. 요청·화면 상태는 ViewModel에 두되 Context·View·비밀번호 저장 상태는 두지 않아요.

## 가정·한계와 영향

- 서버 #9가 없으므로 로컬 HTTP fixture의 성공을 실제 가입·로그인·메일 수신으로 보고하지 않아요.
- 세션의 영구 저장, 앱 재시작 로그인 유지, 계정 설정·로그아웃·채널과 메일 링크의 토큰 확인 화면은
  이번 첫 작업에 포함하지 않아요. #27 전체를 완료로 처리하지 않아요.
- 기기 도구가 `Agent device access is turned off`를 반환했어요. 이 설정을 우회해 기기를 조작하지 않아요.
  실제 화면·키보드·회전·스크린샷 검증은 기기 접근이 가능한 세션에서 확인해야 해요.

## 검증과 재검토 조건

2026-10-31 macOS, `mise.toml`의 Bun 1.4.4·JDK 25.0.5+8, Android SDK 37에서 확인했어요.

- 인증 JVM 테스트 22개: 입력 정규화·Unicode 경계, MockWebServer의 HTTP 요청·오류·헤더/본문 시간 초과,
  redirect·자동 재전송 거부, 상태 전환·명시적 재시도·중복 제출·화면 해제 후 응답을 확인했어요.
  확인 메일 재요청 실패 경로는 수정 전 실패·수정 후 통과를 확인했어요.
- `mise run check`: API 226개, API 도구 16개, 공통 도구 49개, Android 30개 테스트가 통과했어요.
  Android Spotless·lint·debug 빌드와 Terraform 두 root의 로컬 검사도 통과했어요.
  lint 오류는 0개이며 도구·의존성 새 버전과 미사용 색상 경고 9개가 남아 있어요.
- `mise exec -- apps/android/gradlew -p apps/android :app:assembleRelease`: 성공했어요.
  debug 진입점 없이도 제품용 컴포넌트가 컴파일되는 것을 확인했으며 배포 검증은 아니에요.
- `git diff --check`와 변경 문서의 로컬 링크를 확인했어요.
- 기기 접근 제한으로 실제 화면·키보드·회전·큰 글꼴·스크린샷 검증은 실행하지 못했어요.
  JVM 테스트의 상태 검증을 실제 Android 생명주기·UI 실행 결과로 대신하지 않아요.

#28의 호스트·세션 계약이 정해지거나 #9의 응답이 확정 계약과 달라지면 연결 경계를 재검토해요.
연결 방법은 [개발 가이드](../development.md#인증-화면과-공통-앱-기반-연결)에 있어요.

## 반론과 변경 이력

- 2026-10-31: 공통 기반 미구현 상태를 확인하고 인증 화면과 HTTP 요청까지만 독립적으로 준비해요.
- 2026-10-31: 확인 메일 재요청 실패 시 가입 입력으로 돌아가던 문제를 회귀 테스트로 재현하고,
  확인 화면 상태를 요청 성공·실패와 분리해 수정했어요.
