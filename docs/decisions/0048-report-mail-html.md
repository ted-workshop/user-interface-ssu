# ADR-0048: 채널 리포트 메일을 Qletter 스타일의 안전한 HTML로 렌더링해요

- 상태: 확정
- 작성일: 2026-11-24
- 확정일과 근거: 2026-11-24, 사용자의 "요약 메일에 스타일을 적용해 달라"는 요청 범위 안에서 렌더러 선택·보안 경계를 자율 판단했어요.
- 관련 기록: [ADR-0012](0012-gmail-smtp-email-foundation.md)의 Gmail SMTP·text/HTML 발송, [ADR-0037](0037-channel-report-delivery.md)의 채널 리포트 발송, [ADR-0017](0017-report-generation-parity.md)의 리포트 마크다운 형식을 적용해요.
- 구현·검증 상태: 렌더러와 단위 검사, 로컬 workerd 전체 검사를 완료했어요. 실제 Gmail·Apple Mail·Outlook의 화면과 다크 모드는 확인하지 않았어요.

## 문제와 현재 상태

채널 자동 요약 메일이 도착하지만 HTML 본문이 `<pre>`에 마크다운 원문을 넣은 형태라
제목·목록·인용·링크가 서식 없이 보여요. 리포트 본문은 [요약 프롬프트](../../apps/api/src/summary.ts)가
`##` 소제목, **굵게**, 번호·불릿 목록, `---`, 유튜브 시간 링크를 포함한 마크다운으로 생성해요.
[ADR-0012](0012-gmail-smtp-email-foundation.md)는 text·HTML 본문을 함께 보내되 리포트 렌더러를 후속 범위로 남겼어요.

## 결정

- `apps/api/src/report-mail.ts`의 `renderReportEmail(title, bodyMarkdown)`이 메일용 HTML 문서 전체를 만들어요.
  발송 실행기인 `runDelivery`는 저장된 제목·마크다운만 넘기고 SMTP·재시도 계약은 바꾸지 않아요.
- 마크다운 해석은 `marked` 18.2.1에 맡기고, 렌더러를 직접 등록해 메일에서 필요한 태그와 인라인 스타일만 출력해요.
  제목은 h2부터 시작해 메일 상단의 h1 제목과 중복되지 않게 해요.
- 스타일은 Qletter Android 화면과 같은 흑백 팔레트(`#0D0D0D`, `#404040`, `#767676`, `#E8E8E8`, `#F7F7F8`)를 써요.
  640px 카드, 4px 상단 강조선, 16px 본문, 1.75 줄 간격을 인라인으로 지정해요.
  `<style>` 블록은 Gmail·Apple Mail 등이 제거·제한할 수 있어 사용하지 않아요.
- 모델이 출력한 원문 HTML은 실행하지 않고 이스케이프해 글자로 보여줘요.
  링크는 `http`·`https`만 `href`로 만들고, `javascript:`·`file:` 같은 스킴과 사용자 정보가 있는 URL은 링크 없이 글자만 남겨요.
  이미지는 원격 추적을 막기 위해 불러오지 않고 `[이미지] 대체 문구`로 바꿔요.
- text 본문은 기존처럼 마크다운 원문을 유지해요. HTML을 표시하지 못하는 클라이언트의 대체 본문이에요.
- 메일 하단에는 앱과 같은 "AI가 작성한 리포트" 안내를 넣어요. 발송은 채널 자동 요약에만 연결돼 있어
  상단에 `QLETTER · 채널 자동 요약`을 표시해요.
- 렌더링 예외는 SMTP 호출 전에 `invalid_input` 실패로 남겨 재시도하지 않아요. SMTP를 호출하지 않았는데
  결과 불명으로 처리해 발송 이력을 막지 않기 위해서예요.

## 근거와 대안

2026-11-24에 확인한 [marked의 renderer 문서](https://marked.js.org/using_pro#renderer)는 토큰 단위 renderer 재정의와
`this.parser.parseInline` 사용법을 설명해요. [Workers 문서](https://marked.js.org/using_pro#workers)와 설치한 18.2.1의
타입·ESM 빌드는 Node 전용 API 없이 Workers에서 실행되는 경로를 제공해요. 마크다운 파서를 직접 작성하는 대신
검증된 파서를 쓰고, 메일에 필요한 출력·보안 규칙만 renderer에서 정했어요.

`marked`는 출력 HTML을 정화하지 않는다고 문서에 밝혀요. 그래서 원문 HTML 처리, 링크 스킴, 이미지 비노출을
renderer에서 명시적으로 막았어요. [DOMPurify](https://marked.js.org/using_pro#hooks) 같은 별도 정화 라이브러리는
DOM이나 Node 의존성이 필요해 Worker 번들·런타임 복잡도를 늘리므로, 이미 좁힌 출력 태그 집합에는 추가하지 않았어요.

대안으로 마크다운 부분집합만 처리하는 자체 파서를 둘 수 있어요. 의존성은 늘지 않지만 중첩 목록·표·인라인 조합의
예외를 계속 관리해야 하고, 이미 검증된 파서가 줄여 주는 복잡도가 더 크다고 판단했어요.
`<style>` 블록에 CSS를 모으는 방법은 마크업은 짧아지지만 클라이언트별 head 스타일 지원 차이 때문에 채택하지 않았어요.
외부 HTML 변환 서비스를 호출하는 방법은 저장된 본문만으로 발송한다는 기존 계약과 장애·개인정보 경계를 늘려 채택하지 않았어요.

## 가정·한계와 영향

- `body_markdown` 형식과 저장 데이터는 바뀌지 않아요. 이미 저장된 리포트도 다음 발송·재시도 때 새 렌더러를 사용해요.
- text 본문은 계속 마크다운 원문이에요. text만 표시하는 클라이언트에서는 기존과 같은 `##`, `**` 표기가 보여요.
- 메일 클라이언트의 CSS 지원 차이로 둥근 모서리·`max-width`·`text-underline`이 일부에서 다르게 보일 수 있어요.
  다크 모드 자동 반전과 Outlook 데스크톱 렌더링은 확인하지 않았어요.
- `marked`가 18.2.1로 고정돼요. 파서 업데이트는 렌더러 토큰 계약과 보안 검사를 함께 확인한 뒤 진행해야 해요.
- 원문 HTML을 글자로 보여 주므로 악성 태그가 메일 본문에 텍스트로 남을 수 있어요. 실행되지는 않아요.

## 검증과 재검토 조건

- `report-mail.test.ts`에서 제목 이스케이프, h2·목록·굵게·시간 링크·인용·표·코드 렌더링,
  원문 `<script>`·`<img>` 비실행, `javascript:`·`file:` 링크 비활성, 원격 이미지 비로드를 확인해요.
- `jobs.test.ts`의 발송 검사는 주입된 `<script>`가 HTML에서 `&lt;script&gt;`로만 남는 기존 기대를 유지해요.
- 2026-11-24 로컬에서 `apps/api` typecheck와 workerd 476개·Bun tools 16개 검사를 통과했어요.
- 실제 수신 주소로 새 HTML 메일을 보내 Gmail 웹·모바일과 Apple Mail에서 확인하기 전에는 화면 검증 완료로 보지 않아요.
- 재검토 조건: 주요 메일 클라이언트에서 레이아웃이 깨지거나, 다크 모드·이미지 차단 동작이 제품 기대와 다르면
  인라인 스타일 값과 wrapper 구조를 다시 정해요. 마크다운 이외 형식이나 첨부가 필요해지면 렌더러 경계를 새로 설계해요.

## 반론과 변경 이력

- 2026-11-24: 사용자가 요약 메일의 마크다운 원문 표시를 지적해 채널 리포트 HTML 렌더러를 추가했어요.
  원격 메일 클라이언트 화면 검증은 남아 있어요.
