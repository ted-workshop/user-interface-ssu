# ADR-0031: 리포트 공개는 개인 규칙 행의 순번으로 관리해요

- 상태: 확정
- 작성·확정일: 2026-11-05
- 확정 근거: 사용자가 2026-11-05에 리포트 단위 공개, 순번 승계, 직접 철회, 순번 없는 소멸 뒤 초기화, 댓글 삭제 표시, 공개 시각순 목록을 정했어요. 저장 방식은 승인 범위 안에서 판단했어요.
- 관련 기록: [ADR-0020](0020-shared-analysis-and-report-permissions.md)의 공통 보고서·권한, [ADR-0026](0026-report-read-http.md)의 상세 조회, [ADR-0029](0029-collections-http.md)의 모음을 적용해요.
- 구현·검증 상태: 공개·철회·승계, 공개 목록·검색, 댓글 HTTP를 로컬에서 구현·검사했어요. 원격 CI·배포·Android 연결은 확인하지 않았어요.

## 문제와 현재 상태

[#23](https://github.com/ted-workshop/user-interface-ssu/issues/23)은 리포트를 로그인 사용자 전체에 공개하고 댓글을 나누게 해요.
`0003`의 공개 규칙 행은 리포트당 하나이고 `user_id`가 반드시 NULL이라, 공개한 사람과 순번을 저장할 곳이 없어요.

## 결정

- `0008_report_publication.sql`에서 개인 규칙 행에 `publish_requested_at`을 더해요. 공개를 누른 시각이고,
  가장 이른 행의 사용자가 현재 공개한 사람이며 나머지는 순번이에요. 공개 규칙 행은 지금처럼 리포트당 하나예요.
- `PUT /v1/reports/{id}/publication`은 보관함에 있는 리포트를 공개하거나 순번으로 등록해요. `published`, `publishedAt`, `isPublisher`를 돌려줘요.
- `DELETE /v1/reports/{id}/publication`은 현재 공개한 사람만 할 수 있고 순번과 상관없이 공개 전체를 닫아요.
  다른 사용자는 `403 PUBLICATION_FORBIDDEN`, 보관함에 없으면 `404`, 이미 닫혀 있으면 `204`예요. 철회는 댓글을 남겨요.
- 공개한 사람이 보관 관계를 지우면 다음 순번이 이어받고 공개 시각은 유지돼요. 순번이 없으면 trigger가 공개 규칙을 지우고
  그때까지의 댓글에 `archived_at`을 남겨, 다시 공개하면 새 공개 시각으로 이전 댓글 없이 시작해요.
- 댓글 삭제는 `deleted_at` 표시예요. 숨긴 표시는 되돌릴 수 없고 본문 등 나머지 열은 계속 바꿀 수 없어요.
- `GET /v1/reports/public`은 내 보관함과 분리된 공개 목록이에요. 상세는 기존 `GET /v1/reports/{id}`를 같이 써요. 공개 시각 최신순이고 제목 또는 채널명을 검색하며,
  삭제·보관 표시가 없는 댓글 수를 함께 돌려줘요. 공개한 사람의 정보는 응답에 넣지 않아요.
- 댓글 HTTP는 `/v1/reports/{id}/comments`예요. 공개 규칙이 없으면 404이고, 작성자는 닉네임과 `canDelete`만 보여줘요.
- 앱이 공개 버튼 상태를 그리도록 `GET /v1/reports/{id}/publication`을 둬요.
- 공개 목록·댓글·공개 경로를 모두 `/v1/reports` 아래 `reports.ts`에 두어 세션 검사를 한 번만 해요. `/public`은 `/:id`보다 먼저 등록해요.

## 근거와 대안

- 회의에서 별도 공유 테이블 없이 권한 테이블을 확장하기로 했어요. 순번을 공개 규칙 행 여러 개로 두면 `0003`의 CHECK와
  partial unique를 바꾸려고 FK가 걸린 `report_permissions`를 다시 만들어야 해요. 개인 규칙 행에 열을 더하면 `ALTER TABLE`만으로 끝나요.
- 보관 관계 삭제가 곧 순번에서 빠지는 것이라 승계가 따로 저장할 상태 없이 이뤄져요.

## 가정·한계와 영향

- 현재 API에는 탈퇴와 보관함에서 빼기가 없어요. 승계·소멸은 테스트에서 권한 행을 직접 지워 확인해요.
- 순번 기록 없이 이미 있던 공개 규칙(테스트·수동 데이터)은 공개를 누른 첫 사용자가 공개한 사람이 돼요.

  공개 목록 정렬·페이지·검색·비공개 제외, 댓글 작성·조회·페이지·댓글 수, 본인 댓글만 삭제, 철회 중 댓글 차단, 입력 오류를 다뤄요.
