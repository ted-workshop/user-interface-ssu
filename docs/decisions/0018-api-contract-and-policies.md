# ADR-0018: 계정별 API 계약과 인증·요약·자동화 정책을 맞춰요

- 상태: 확정
- 작성·확정일: 2026-10-27
- 확정 근거: #7·#8 진행 요청 범위 안에서 기존 제품 명세를 구체화한 판단이에요.
- 관련 기록: [ADR-0001](0001-workers-d1-free-tier.md), [ADR-0003](0003-shared-modules-sync-async.md),
  [ADR-0012](0012-gmail-smtp-email-foundation.md), [ADR-0017](0017-report-generation-parity.md),
  [저장 모델 작업 #8](https://github.com/ted-workshop/user-interface-ssu/issues/8)
- 구현·검증 상태: [API 계약](../api-contract.md)을 작성했어요. 제품 HTTP·인증·Android 구현은
  후속 이슈예요. #5의 현재 설정 실제 생성·지원 범위·할당량, 앱/API 담당자의 예제 검토는 미완료예요.
  이 기록의 확정은 #7 전체 완료·공급자 성공·배포를 뜻하지 않아요.

## 문제와 현재 상태

Android와 API 작업자가 인증·요약 상태·중복·재시도를 각자 정하면 같은 동작을 연결할 수 없어요.
현재 [API](../../apps/api/src/app.ts)는 health와 JSON 오류뿐이며 제품 계약의 기존 소비자는 없어요.
[명세](../qletter/02-functional-spec.md) F-01~F-09·F-11과 #9의 닉네임 요구를 기준으로 해요.
현재 Gemini 조건은 ADR-0017이고 마지막 실제 요청은 HTTP 429예요. 과거의 다른 요청 조건 성공을
현재 지원으로 취급하면 잘못된 길이·사용량 보장과 DB 정책을 만들게 돼요.

## 결정

- `/v1`에서 직접 자원 객체·안정적인 오류 code·UTC 시간·UUID·keyset 목록을 사용해요.
  기존 health·404·500은 유지해요. 기능 구현 없이 공통 패키지·코드 생성기를 추가하지 않아요.
- 이메일 확인 후 opaque 세션을 발급해요. 로그인 이메일과 수신 주소는 독립적으로 확인해요.
  토큰은 32바이트 난수이고 인증 비교 열에는 hash만 저장해요. 메일 outbox의 원문 토큰은 별도
  서버 키로 암호화하고 발송·만료 뒤 제거해요. 세션 절대 만료 30일, 메일 확인 24시간, 복구 30분은
  이번 초기 보안·사용성 정책이며 공급자 수치가 아니에요. 복구 후 모든 세션을 폐기해요.
- MFA가 없으므로 비밀번호는 15~128 code point예요. hash 라이브러리·비용은 #9에서 OWASP 권고와
  Workers 실측을 함께 확인해요. 닉네임은 2~20 code point, 중복 허용이며 계정 ID로 소유자를 구별해요.
- 중복 가입·확인/복구 메일 요청은 계정 존재 여부를 노출하지 않아요. 요청 제한은 계약의 초기 수치로
  시작하며 #9가 분산 우회·CPU·정상 사용자 차단을 측정해요. 영구 잠금은 채택하지 않아요.
- 같은 계정·영상의 요청과 결과를 재사용하고 생성 경로는 고정해요. 조회 재시도는 GET, 분석 재시도는
  마지막 시도 번호를 비교하는 명시적 POST로 나눠 응답 유실이 새 분석을 만들지 않게 해요.
- 분석은 계정당 한 번에 하나, 총 3시도 상한이에요. quota·결과 불명은 자동 재시도하지 않아요.
  SMTP도 결과 불명은 중단하고 확실한 일시 거부만 1분·5분 간격의 총 3시도로 제한해요.
- 채널은 최초 성공한 관찰 ID 집합을 기준으로 삼아요. 기본 360분, 선택 60·360·1,440분은 초기
  경과 시간 정책이에요. 빈 채널도 시작 완료를 기록하고 중지·삭제로 대기 발송을 취소해요.
- 리포트는 먼저 보관하고 수신 대상은 그 시점의 확인된 주소로 고정해요. 직접 결과를 소급 발송하지
  않아요. `sent`는 SMTP 접수이며 수신·열람과 구분해요. 삭제는 이력을 보존하는 논리 삭제예요.
- 지원 영상 길이·실제 모델 한도·계정별 일일 상한은 #5의 증거가 없으므로 미확정으로 남겨요.
  새 분석·자동화 접수는 실제 생성·원본 대조·운영 상한이 준비될 때 활성화해요.
  DB 저장 구조와 독립적인 계약은 먼저 구현할 수 있어요.

## 근거와 대안

2026-10-27 공식 자료와 현재 코드를 확인했어요.

- [OWASP 인증 지침](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)은
  MFA 없는 비밀번호의 길이, 열거 방지·요청 제한을 다뤄요. 15자 최소를 이 근거로 선택해요.
  30일 세션·24시간/30분 토큰·요청 제한 수치는 공식 의무값이 아니라 재로그인 부담과 남용 위험을
  비교한 초기 정책이에요. 실제 사용·공격 방어 측정 뒤 조정해요.
- [OWASP 복구 지침](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)은
  일회용·만료 토큰, 계정 존재 여부에 독립적인 안내와 재설정 후 세션 폐기를 뒷받침해요.
- [OWASP 세션 지침](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)을
  따라 충분한 난수와 서버 측 폐기를 선택해요. JWT+refresh는 분산 검증에 장점이 있지만 현재
  단일 Worker·D1 구조에서는 로그아웃·복구 시 즉시 폐기할 상태가 필요해 opaque 세션이 더 작아요.
- 가입 즉시 로그인은 화면 수가 적지만 확인되지 않은 이메일·복구 경로를 신뢰하게 돼요.
  이메일 소유 확인을 먼저 하고, 확인 링크만으로 타인이 등록한 비밀번호를 활성화하지 않아요.
- 성공 envelope·offset 페이지도 가능해요. 현재 오류 envelope만 있으므로 성공의 중복 wrapper를
  추가하지 않고, 계속 추가되는 리포트는 keyset으로 읽어요. 전체 건수 조회 비용도 피할 수 있어요.
- 채널 과거 영상을 일괄 생성하거나 메일 실패 때 재분석하면 기존 명세와 비용·중복 규칙을 깨요.
  관찰 기준·저장된 본문 재사용을 선택해요. 실측 성능 우위라는 주장은 아니에요.
- 길이·할당량을 추정해 확정하면 후속 구현이 허위 보장에 의존해요. #5 gate를 남기는 대신
  계정·상태·소유권과 저장 모델 작업을 이어가요. 모델/API를 자동 교체하는 대안은 ADR-0017과 충돌해요.

## 가정·한계와 영향

요청 제한·세션 만료·확인 주기는 초기 정책이며 부하·공격·기기 사용성의 실측값이 아니에요.
지원 길이·사용량 gate 때문에 #7을 완전히 닫을 수는 없어요. #8은 이 수치에 의존하지 않는
저장 관계·이력·제약을 구현해요. #9가 hash·메일 outbox·rate limit을, #10·#14가 실제 실행 수단과
확인 작업 저장을 구현해요. Workflows 채택을 이 계약으로 확정하지 않아요.
기존 제품 데이터가 없어 호환 이관은 없으며 토큰·개인 주소는 응답·로그·artifact 공개 대상이 아니에요.

## 검증과 재검토 조건

API 계약의 시나리오를 명세 AC-01~AC-09·AC-11과 대조해요. Android/API 담당자는
로그인 실패·동일 영상·조회 재시도·시도 번호 기반 분석 재시도의 예제를 구현 전 검토해요.
원격 담당자 검토는 실행하지 않았어요. DB 수준 구현·검증은 #8에서 이어가요.
실제 지원 범위·할당량, 인증 CPU, 정상 사용자 차단, 긴 보관함 조회 비용이 확인되면 정책을 재검토해요.
계약 변경은 소비자·저장 모델·관련 ADR을 함께 갱신해요.

## 반론과 변경 이력

- 2026-10-27: #5가 끝나지 않아 전체 작업을 기다리는 대안을 검토했어요. 공급자 수치를 확정하지
  않고 공통 계약·저장 구조를 먼저 구현해요. 실제 생성·한도·담당자 검토 gate는 미해결로 유지해요.
