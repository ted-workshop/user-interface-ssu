# ADR-0045: 담기 시트는 일부만 저장돼도 바로 알려요

- 상태: 확정
- 작성일: 2026-11-22
- 확정 근거: #69 범위에서 PR #82 리뷰 지적을 고치면서 정한 구현 판단이에요.
- 관련 기록: [ADR-0029](0029-collections-http.md), [ADR-0038](0038-android-foundation.md), [ADR-0039](0039-android-feature-packages.md)
- 구현·검증 상태: 구현과 로컬 검사를 했어요. 리포트 상세 연결과 실제 TalkBack 확인은 남아 있어요.

## 문제와 현재 상태

- 모음 여러 개 중 일부만 저장된 뒤 취소하면, 서버는 바뀌었는데 시트를 띄운 화면은 몰랐어요.
- 가로 화면에 큰 글꼴이면 목록 높이가 0이 되고 취소·완료 버튼이 잘렸어요.

## 결정

- 저장 한 번에서 하나라도 성공하면 `REQUEST_KEY` 결과를 한 번 보내요. 전부 성공했을 때만 시트를 닫아요.
- 띄운 화면은 결과를 받을 때마다 다시 불러와요. 일부 실패 뒤 다시 저장하면 결과가 한 번 더 가요.
- 제목·설명·목록·오류를 같이 스크롤하고, 입력칸과 취소·완료는 아래에 남겨요. 오류가 뜨면 그 문구로 스크롤해요.

## 근거와 대안

- 닫을 때 보내기: 결과가 한 번으로 줄지만, 앱이 정리되면 알릴 기회가 없어서 쓰지 않았어요.
- 띄운 화면이 `onResume`에서 다시 읽기: 시트는 Dialog라 닫혀도 `onResume`이 불리지 않아서 쓰지 않았어요.
- 시트 전체 스크롤: 단순하지만 모음이 많으면 완료 버튼이 맨 아래로 밀려서 쓰지 않았어요.

## 가정·한계와 영향

- 목록을 펼쳐 놓고 스크롤해서 줄을 재활용하지 않아요. 모음을 100개까지만 받아서 감수해요.
- 가로에서는 키보드가 화면을 덮어요. 키보드의 완료로 새 모음을 만들 수 있게 했어요.
- 체크 상자 테두리색은 피그마 공통색을 유지해요. 대비는 디자인에서 따로 정해요.

## 검증과 재검토 조건

- `AddToCollectionSheetTest`: 일부 실패·재시도, 체크 복원, 결과 한 번 전달
- 모음을 100개보다 많이 받게 되면 목록 구조를 다시 정해요.

## 반론과 변경 이력

- 2026-11-22: PR #82 리뷰에서 일부 저장 뒤 취소와 가로 화면 잘림을 지적받아 반영했어요.
