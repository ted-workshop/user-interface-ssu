# Qletter 제품 매니페스트

> **볼 건 줄이고, 알아야 할 것만.**
>
> 내가 고른 영상과 채널의 핵심을 읽을 수 있는 글로 만들어요.

Qletter는 YouTube 영상 링크로 한 편을 요약하거나, 관심 채널의 새 영상을 자동으로 받아보는 안드로이드 앱을 지향해요. 사용자인터페이스 과목 팀프로젝트로서 처음 보는 사람도 이해할 수 있는 조작과 피드백을 중요하게 봐요. 이 매니페스트는 팀이 기능과 디자인을 선택할 때 함께 사용할 제품 원칙이에요. 구체적인 범위는 [PRD](01-prd.md)에 정리해요.

## 1. 사용자의 시간을 아껴요

좋은 영상은 많고 모두 볼 시간은 부족해요. 핵심을 이해한 뒤 필요한 부분만 더 보거나 자신의 일로 돌아갈 수 있게 도와요.

서비스에 오래 머무는 시간보다 필요한 내용을 이해했는지를 중요하게 봐요.

## 2. 한 편으로 시작할 수 있어야 해요

사용자는 Google 계정으로 로그인한 뒤 영상 링크 하나로 시작해요. 결과를 읽기 전에 채널 등록이나 메일 설정을 먼저 요구하지 않아요.

계속 받아보고 싶어질 때 채널 자동 요약을 선택할 수 있어요.

## 3. 선택은 사용자가 해요

무엇을 읽을지는 사용자가 고른 영상과 채널에서 출발해요. 영상 한 편을 요청한 것을 채널 구독이나 이메일 수신 동의로 확대하지 않아요.

자동화를 켜고 끄는 행동과 그 결과를 쉽게 이해할 수 있어야 해요.

## 4. 짧게 훑고 깊게 읽어요

세 줄 요약에서 핵심을 파악하고 본문에서 맥락을 읽어요. 목차와 시간 링크는 필요한 부분으로 빠르게 이동하도록 도와요.

글자 수를 채우기 위해 설명을 늘리지 않아요. 원본의 중요한 맥락을 지키면서 읽기 부담을 줄여요.

## 5. 원본으로 돌아갈 길을 남겨요

리포트는 AI가 원본을 정리한 해석이에요. 중요한 주장·수치·장면은 원본에서 다시 확인할 수 있어야 해요.

원본에 없는 정보를 자신 있게 덧붙이지 않고, 확인할 수 없는 시점을 추측해 링크로 만들지 않아요. 출처가 있다는 사실과 해석이 정확하다는 판단을 구분해요.

## 6. 기다림과 실패를 설명해요

요약 중인지, 결과를 만들지 못했는지, 글은 있지만 메일만 실패했는지를 구별해요. 사용자가 다음에 할 수 있는 행동을 함께 보여줘요.

확인하지 않은 완료 시간이나 진행률을 보여주지 않아요. 상태를 불러오지 못한 것을 작업 실패로 단정하지 않아요.

## 7. 이미 만든 가치를 보존해요

메일이 실패해도 리포트는 남아요. 채널을 삭제해도 읽고 모아둔 글은 사라지지 않아요.

같은 계정에 같은 영상의 결과가 있으면 먼저 활용해요. 반복 클릭이나 단순 조회 때문에 분석을 다시 하지 않아요.

## 8. 자동화는 예측할 수 있어야 해요

처음 등록한 채널의 과거 영상을 한꺼번에 처리하지 않는 이유를 알려줘요. 중지하면 무엇이 멈추고 다시 시작하면 무엇을 확인하는지도 설명해요.

사용자가 요청하지 않은 메일이나 원치 않는 반복 처리를 줄여요. 지연이나 접근 제한을 숨기지 않아요.

## 9. 약속은 확인할 수 있어야 해요

빠르다거나 정확하다는 표현은 실제 경험과 평가로 뒷받침해요. 비용과 사용 한도는 이해하기 쉽게 안내해요.

더 많은 기능을 넣기 전에 한 편을 선택하고, 이해하고, 다시 찾는 기본 흐름이 잘 작동하는지 확인해요.

## 10. 내 기록을 안심하고 다시 열어요

로그인은 내 보관함과 채널 설정을 연결하는 과정이에요. 불필요한 가입 입력을 줄이고, 계정을 바꾸면 이전 사용자의 기록을 보여주지 않아요.

뒤로 가기, 앱 재진입, 네트워크 끊김에서도 현재 상태와 다음 행동을 이해할 수 있어야 해요. 로그아웃과 채널 자동화 중지를 구분해서 알려줘요.

## 우리가 쓰는 말

| 상황 | 표현 예시 |
| --- | --- |
| 로그인 | `Google로 계속하기` |
| 첫 요약 | `영상 링크를 넣고, 핵심부터 읽어보세요.` |
| 처리 중 | `영상을 요약하고 있어요.` |
| 같은 결과 발견 | `이미 만든 리포트가 있어요. 바로 읽어보세요.` |
| 첫 채널 등록 | `첫 확인 이후 발견한 새 영상부터 요약해요.` |
| 직접 요약 완료 | `리포트를 보관함에 저장했어요.` |
| 메일 실패 | `리포트는 저장됐지만 메일을 보내지 못했어요.` |
| 원본 확인 | `중요한 내용은 원본 영상에서 확인해 주세요.` |

## 새로운 아이디어를 평가하는 질문

1. 내용을 선택하고 이해하고 다시 찾는 데 도움이 되나요?
2. 처음 온 사람이 한 편의 가치를 경험하기 쉬워지나요?
3. 원본의 맥락과 출처를 유지하나요?
4. 대기·성공·실패를 이해하고 복구할 수 있나요?
5. 불필요한 반복 처리와 원치 않는 발송을 줄이나요?
6. 실제 사용자 경험으로 효과를 확인할 수 있나요?
