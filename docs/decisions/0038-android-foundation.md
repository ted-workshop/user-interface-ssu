# ADR-0038 Android 탭과 로그인 세션의 공통 기반

- 상태 · 확정. 2026-11-07 [#28](https://github.com/ted-workshop/user-interface-ssu/issues/28)의 공통 기반 범위에서 결정했어요.
- 관련 기록 · [API 계약](../api-contract.md), [인증 서버의 ADR-0028](0028-auth-http.md), [화면 연결 방법](../development.md#android-화면에서-공통-기반-사용).
- 구현·검증 · 구현 커밋 `97c42d2`에서 WSL Android 검사와 앱·테스트 APK 빌드를 확인했어요. 에뮬레이터에서 촬영한 전후 화면은 [PR #50](https://github.com/ted-workshop/user-interface-ssu/pull/50)에 있어요.

## 문제와 현재 상태

main의 Android 제품 진입점에는 빈 화면이 있었고 debug 앱은 개발 서버 점검 화면으로 시작했어요.
#27·#29 담당자가 색상과 탭, 개인 API 요청에 같은 규칙을 적용할 수 있어야 해요.
[#38](https://github.com/ted-workshop/user-interface-ssu/pull/38)은 병합 없이 닫혀 있어서 해당 브랜치에 의존하지 않아요.

## 결정과 근거

- 제공받은 Figma PNG 6장과 원본 Color 변수 이름·값 17개를 기준으로 탭 순서, 선택 텍스트와 선 아이콘을 구현했어요. 가림막은 검정 78%를 8비트 알파 199로 표현해요. 제공된 한 벌의 색상을 두 시스템 모드에서 유지해요.
- Java·XML 프로젝트에 이미 있는 Material의 BottomNavigationView가 접근성 선택 상태와 화면 재생성 시 메뉴 상태를 맡아요. Fragment 컨테이너 하나에서 탭에 해당하는 화면을 보여줘요. 탭별로 Activity를 만드는 방식은 세션 전환 때 폐기할 진입점이 늘어나요.
- 인증 화면은 로그인 결과만 넘겨요. 앱 범위의 세션 저장소가 Android Keystore 키로 토큰과 만료 시각을 함께 암호화해 백업 제외 디렉터리에 원자적으로 저장해요. 서버 주소도 인증된 암호문에 묶어요. 메모리만 사용하면 앱 재시작 때 다시 로그인해야 해요.
- OkHttp 클라이언트가 개인 요청을 만들 때의 세션과 API 주소를 고정해요. 요청 전과 응답 직후의 세션을 대조해요. 현재 세션의 401은 로그인을 해제하고, 연결 실패 때는 저장 상태를 유지해요. 계정 변경 후 늦은 UI 콜백은 각 화면에서도 생명주기에 맞춰 폐기해요.

## 가정과 영향

로그인·계정 설정 화면은 #27, 모음·리포트 댓글은 #29에서 연결해요. 공통 탭에는 예시 리포트나 임시 로그인 계정을 넣지 않았어요.
release 주소는 ADR-0028에 기록된 HTTPS Worker예요. debug는 기존 에뮬레이터·USB 주소 설정을 사용해요. 화면 색상이나 API origin이 바뀌면 리소스 또는 빌드 설정을 검토해요.

## 검증과 재검토 조건

2026-11-07 JDK 25에서 저장소 버전의 OkHttp·MockWebServer·JUnit과 실제 변경 소스로 JVM 테스트 10개를 별도 실행했어요. 현재·이전 세션의 401, 이전 계정 요청, 리디렉션, 서버 오류, 토큰 전달, 만료 시각 처리가 통과했어요. Gradle Spotless와 XML 리소스의 정적 대조도 확인했어요.

2026-11-07 작성자의 Ubuntu(WSL)에서 `97c42d2`로 `mise run android:check`(Spotless·lintDebug·testDebugUnitTest·assembleDebug)를 통과했어요. 이어서 `:app:assembleRelease :app:assembleDebugAndroidTest`도 성공했어요. 마지막 빌드 출력은 32초, Gradle 작업 94개 중 73개 실행·21개 최신 상태였어요.

수정본 `000ed45`에서 Pixel 7 AVD(Android 17, API 37, x86_64)로 `:app:connectedDebugAndroidTest`를 실행했어요. 패키지 확인 1개와 탭·세션 테스트 6개가 모두 통과했고 `:app:assembleRelease`도 성공했어요. 테스트의 시계를 전진시켜 절전 중 만료된 경우를 재현했어요. [기기별 검사 로그](https://github.com/ted-workshop/user-interface-ssu/actions/runs/43893351527/job/133390157908)에 결과가 있어요. 실제 계정 로그인은 #27 화면을 연결한 뒤 확인해요. 계정 전환 뒤 이전 화면이 복원되거나 기존 세션이 새 요청에 쓰인다면 세션·탐색 경계를 다시 검토해요.

## 반론과 변경 이력

- 2026-11-07 · #38의 인증 화면을 가져오는 대안도 검토했어요. #27 담당자의 범위이고 해당 PR이 닫혀 있어 로그인 결과 전달 메서드만 제공해요.
- 2026-11-13 · 팀 리뷰에 따라 공통 Activity와 탭 Fragment에 View Binding을 적용해요. XML에서 생성한 타입으로 뷰를 참조해 ID나 뷰 타입 변경을 빌드에서 확인할 수 있어요. 탭 Fragment는 뷰를 만들 때 바인딩을 지역 변수로 두고 해당 뷰의 생명주기 동안만 관찰해요.
- 2026-11-13 · 앱 시작 시 세션 복호화를 작업 스레드로 옮겼어요. 홈은 복원을 기다리지 않고 표시하고 복원한 세션이 있으면 사용자 확인을 시작해요. 저장·복원·삭제를 직렬화하고, 복원 전에 끝난 로그인이나 로그아웃 결과를 보존해요.
- 2026-11-16 · 탭 화면은 전환 시 다시 만들어져요. 현재 탭은 제목과 관찰한 세션 상태만 표시해 `replace`를 유지해요. 뒤로 가기 스택에는 탭을 넣지 않아요. #27·#29의 화면에서 입력·스크롤 보존이 필요하면 연결 전에 탭별 상태 저장 또는 다중 back stack을 함께 정해요.
- 2026-11-16 · 앱이 전면으로 돌아오면 실제 만료 시각을 다시 대조해요. 절전 중 멈추는 지연 타이머만으로는 만료를 알릴 수 없어요. 로그인 저장도 복원과 같은 작업 스레드에서 수행하고 결과를 메인 스레드에 전달해요. 기기 테스트는 대상 앱의 캐시 아래에 테스트별 임시 디렉터리를 만들어 세션 파일을 분리해요.
- 2026-11-18 · 서버가 닫은 keep-alive 연결을 다시 쓰다 `unexpected end of stream`으로 실패하던 문제를 고쳐요. OkHttp 전체 재시도(`retryOnConnectionFailure`)는 꺼 둔 채로 두고, 같은 요청을 다시 보내도 서버 상태가 바뀌지 않는 GET·HEAD만 연결 실패 때 새 연결로 한 번 더 보내요. POST·PUT·PATCH·DELETE는 서버가 본문을 받은 뒤 연결이 끊기면 같은 모음이 다시 생성돼 `409`가 되거나 같은 댓글이 두 번 저장될 수 있어 재전송하지 않아요(PR #67 리뷰). 저장 요청을 다시 보내려면 서버 멱등성 키를 먼저 마련해요. JVM 테스트로 GET 복구와 POST 1회 수신을 확인해요.
