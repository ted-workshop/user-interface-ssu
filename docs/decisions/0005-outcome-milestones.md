# ADR-0005: 확인할 결과를 기준으로 마일스톤을 나눠요

- 상태: 확정
- 작성·확정일: 2026-10-20
- 확정 근거: 사용자가 등록한 작업을 마일스톤 단위로 묶자고 요청했어요.
  네 단계의 구체적인 범위와 완료 기준은 기존 명세·선행 관계를 바탕으로 정했어요.
- 관련 기록: [ADR-0004](0004-github-issue-backlog.md), [작업 추적 이슈 #2](https://github.com/ted-workshop/user-interface-ssu/issues/2)
- 구현·검증 상태: 2026-10-20에 GitHub 마일스톤 4개를 만들고 필수 이슈 14개를 배정했어요.
  원격 재조회로 설명·배정·날짜 미지정과 기존 이슈·상위/선행 관계 보존을 확인했어요.
  현재 진행 상태는 GitHub에서 확인해요. API 구현·테스트·배포 완료를 뜻하지 않아요.

## 문제와 현재 상태

추적 이슈와 하위 작업 15개는 개별 범위·완료 기준·선행 관계를 관리해요.
사용자는 여기에 마일스톤을 추가해 작업을 묶자고 요청했어요.
2026-10-20 조회 시 기존 마일스톤과 이슈 배정은 없었어요.

## 결정

GitHub의 마일스톤을 사용하고 각 설명에 해당 단계의 결과와 완료 기준을 적어요.

1. [M1: API 기반과 외부 연동 검증](https://github.com/ted-workshop/user-interface-ssu/milestone/1)은
   Workers·D1 실행과 실제 Gemini·메일 검증, 후속 구현에 사용할 API 계약·스키마까지예요.
2. [M2: 직접 요약 API 시연](https://github.com/ted-workshop/user-interface-ssu/milestone/2)은
   로그인 → 영상 URL → 실제 요약 → 저장 리포트 → 보관함 조회까지예요.
3. [M3: 채널 자동화 API 시연](https://github.com/ted-workshop/user-interface-ssu/milestone/3)은
   채널 등록 → 새 영상 확인 → 자동 요약 → 수신 주소별 메일 전달과 복구까지예요.
4. [M4: 배포 환경의 API 전체 경로 검증](https://github.com/ted-workshop/user-interface-ssu/milestone/4)은
   정확한 커밋·환경에서 실제 공급자·영구 저장·실패 복구와 무료 운영 조건을 확인하는 단계예요.

필수 하위 작업 14개를 배정해요. 전체 목표를 관리하는 #2와 P2 보조 기능인 홈 현황 #16은
마일스톤 없이 남겨요. 날짜는 팀 일정이 정해진 뒤 추가해요.
팀원의 새 이슈도 확인할 결과에 맞는 마일스톤을 선택하고, 목표가 미정인 제안은 배정 없이 추가해요.

## 근거와 대안

[PRD](../qletter/01-prd.md)의 핵심 시연은 직접 요약에서 저장 결과 읽기까지예요.
[기능 명세](../qletter/02-functional-spec.md) F-01~F-04와 F-05~F-08은 각각 직접 요약과 채널 자동화의
사용 흐름을 정해요. 이를 M2·M3의 완료 결과로 사용해 팀원이 무엇을 시연할지 알 수 있게 해요.
M1은 아직 확인하지 않은 공급자 지원 범위와 실행 기반을 후속 구현에 사용할 수 있는지 확인해요.
M4는 로컬 성공과 배포된 환경에서의 실제 동작을 구분해요.

하나의 큰 마일스톤은 관리가 간단하지만 중간에 확인할 결과가 드러나지 않아요.
DB·인증·요약처럼 기술별로만 나누면 담당 범위는 보이지만 사용자 흐름의 완료를 따로 판단해야 해요.
따라서 현재 명세의 시연 흐름과 미검증 경계에 맞춰 네 단계로 묶었어요.
개발 기간이나 속도를 측정해 최적의 단계 수라고 증명한 결과는 아니에요.

## 가정·한계와 영향

번호는 목표 순서예요. 실제 착수는 기존 이슈의 선행 관계를 따르므로 독립적인 조사·설정·초안은
앞서 진행할 수 있어요. 새 이슈를 만들거나 기존 기능 범위·우선순위·담당을 바꾸지는 않아요.
현재 목록은 API 중심이며 Android 제품 화면·기기 시연까지 완료한 것으로 해석하지 않아요.
마일스톤의 이슈 완료 비율은 작업 시간의 비율이나 실제 기능 검증을 대신하지 않아요.

## 검증과 재검토 조건

원격에서 마일스톤 4개의 이름·설명·열린 상태·날짜 미지정과 이슈 14개의 배정을 다시 확인해요.
기존 이슈의 본문·상위/선행 관계·상태·라벨·담당을 보존하고 #2의 링크와 전체 체크리스트를 확인해요.
문서 링크·목차·Git diff를 확인해요. 2026-10-20에는 런타임 변경이 없어 앱 검사를 생략했어요.

2026-10-20 재조회에서 열린 마일스톤 4개와 배정 14개, #2·#16의 미배정을 확인했어요.
기존 이슈의 제목·본문·상태·라벨·담당과 모든 상위/선행 관계가 유지됐고,
#2의 마일스톤 링크와 하위 작업 15개의 체크리스트도 확인했어요.

팀 일정이 정해지면 실제 가용 시간으로 날짜를 논의해요. 공급자 검증이나 명세 변경 때문에
한 단계의 완료 기준을 충족할 수 없거나 팀이 맡기 어려운 크기가 되면 범위와 선행 관계를 재검토해요.

## 반론과 변경 이력

- 2026-10-20: 사용자의 마일스톤 요청으로 중간 목표를 추가했어요.
  ADR-0004의 이슈 관리 방식과 기존 개별 작업을 유지하고 목표별 묶음·완료 기준을 보완해요.
- 2026-10-23: 원격 공유를 준비하며 마일스톤 등록 당시의 검증 날짜를 명시했어요.
  이후 진행 상태는 원격 마일스톤과 이슈에서 확인하도록 안내해요.
