# ADR-0006: push 검사 전에 상속된 Git 저장소 환경을 정리해요

- 상태: 확정
- 작성·확정일: 2026-10-23
- 확정 근거: 문서 원격 반영 요청을 수행하면서 발견한 push 차단 원인을 고치기 위한 자율 판단이에요.
- 관련 기록: [문서 공유 기준](README.md#팀에-공유할-때), [Git hooks 안내](../../CONTRIBUTING.md#git-hooks)
- 구현·검증 상태: 기존 hook에서 회귀 테스트가 실패하는 것을 확인했어요.
  수정 후 검사와 실제 push 결과는 관련 PR에서 확인해요. 앱 기능이나 배포 변경은 없어요.

## 문제와 현재 상태

문서 브랜치의 실제 push에서 `scripts/git-hooks.test.ts`의 임시 저장소 작업이
원래 작업 브랜치에 테스트 커밋을 만들고 저장소 설정을 바꿨어요.
일반 터미널에서 실행한 검사는 통과했지만 hook에서 실행한 검사는 실패했어요.

Git은 hook에 `GIT_DIR`, `GIT_WORK_TREE` 같은 저장소 환경변수를 전달해요.
자식 프로세스가 이를 그대로 상속하면 `git -C <다른 저장소>`를 사용해도 환경변수가 가리키는
저장소에 접근할 수 있어요. 임시 저장소를 만드는 기존 검사도 이 영향을 받았어요.

## 결정

`pre-push`에서 검사 프로세스를 시작하기 전에 `git rev-parse --local-env-vars`로
저장소 환경변수 이름을 얻어 해제해요. 검사 명령·입력·검사 대상 선택은 유지해요.
검사는 원래 작업 디렉터리의 `.git`을 통해 저장소를 찾아요.

## 근거와 대안

[Git hook 공식 문서](https://git-scm.com/docs/githooks#_description)는 다른 저장소나
worktree에 접근하는 hook이 상속된 Git 저장소 환경변수를 정리해야 한다고 설명해요.
같은 문서에서 hook이 작업 트리 루트에서 실행된다는 점도 확인했어요. 확인 날짜는 2026-10-23이에요.

테스트의 Git 함수만 고치면 다른 검사 도구가 별도 저장소를 사용하는 경우는 보호하지 못해요.
따라서 검사를 시작하는 경계에서 환경을 정리해요. 개별 테스트를 건너뛰거나 hook을 끄지 않아요.

## 가정·한계와 영향

검사 도구가 원래 작업 디렉터리 또는 명시한 저장소 경로를 사용한다는 전제예요.
Git의 저장소 환경변수를 일부러 전달해야 하는 새 검사가 생기면 해당 자식 프로세스에만 지정해요.
API·Android 코드, 원격 리소스와 운영 데이터는 바뀌지 않아요.

## 검증과 재검토 조건

실제 `pre-push` 파일을 실행하는 회귀 테스트에서 hook 환경을 재현해요.
검사 도구가 두 번째 저장소의 설정만 바꾸고 원래 저장소의 설정을 보존하는지 확인해요.
기존 hook에서는 원래 저장소의 설정이 바뀌어 실패하는 것을 확인했어요.
수정 후 전체 검사와 실제 브랜치 push를 실행하고 원래 브랜치·설정·작업 트리가 유지되는지 확인해요.

다른 저장소 접근이나 Git 환경을 요구하는 검사 도구가 추가되면 이 실행 경계를 다시 검토해요.

## 반론과 변경 이력

- 2026-10-23: 문서 공유 중 실제 push에서 확인한 저장소 오염을 복구하고,
  Git 공식 지침에 따라 hook의 환경 정리와 회귀 테스트를 추가했어요.
