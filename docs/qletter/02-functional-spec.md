# Qletter 기능 명세

Qletter는 YouTube 영상 한 편을 링크로 요약하거나, 등록한 채널의 새 영상을 자동으로 요약해주는 안드로이드 앱이에요. 결과는 한국어 리포트로 읽고 보관해요.

이 문서는 사용자인터페이스 과목 팀프로젝트를 위한 기능 설계안이에요. 요약 요청·보관함·채널·설정은 로그인한 계정별로 제공해요. 제품의 목적과 범위는 [PRD](01-prd.md), 화면 구성은 [와이어프레임](03-wireframes.md)을 참고해요. **수용 기준**은 기능이 의도대로 동작하는지 확인할 조건이에요.

## 1. 용어

| 용어 | 의미 |
| --- | --- |
| 직접 요약 | 사용자가 영상 URL 하나를 넣어 요청한 요약이에요. |
| 채널 자동 요약 | 등록한 채널에서 새 영상을 발견해 만드는 요약이에요. |
| 리포트 | 핵심 요약·주제별 설명·원본 링크를 담은 영상 한 편의 결과물이에요. |
| 보관함 | 완성한 리포트를 모아두고 다시 찾는 공간이에요. |
| 시간 링크 | 원본 영상의 특정 시점으로 이동하는 링크예요. |
| 확인 주기 | 등록한 채널에 새 영상이 있는지 살펴보는 간격이에요. |

## 2. 기능별 동작

### F-01 · URL 직접 요약

- **입력**: YouTube 영상 URL 하나예요. 일반 영상 주소, 짧은 공유 주소, Shorts와 종료된 라이브 영상 주소를 대상으로 검토해요.
- **행동**: `영상 요약` 화면에서 URL을 넣고 `요약하기`를 눌러요.
- **결과**: 영상 전체의 리포트를 만들고 보관함에 저장해요. 채널 등록이나 이메일 설정은 필요하지 않으며 자동 메일도 보내지 않아요.
- **중복 처리**: 주소 모양이 달라도 같은 영상이면 같은 계정의 기존 결과나 진행 요청을 찾아 연결해요. 다른 사용자의 비공개 결과를 보여주는 것은 허용하지 않아요.
- **예외**: 채널·재생목록만 있는 주소, 여러 URL, 잘못된 주소는 입력 단계에서 안내해요. 읽을 수 없는 영상은 실패 이유를 알려줘요.
- **수용 기준 AC-01**: 유효한 URL 하나로 시작할 수 있고, 같은 영상을 반복 클릭해도 불필요한 중복 분석이 발생하지 않아요.

시간 정보가 붙은 URL도 첫 버전에서는 영상 전체를 요약해요. 비공개·삭제·로그인 필요 영상과 진행 중인 생방송은 초기 지원 범위에서 제외해요. 정확한 지원 범위와 길이 제한은 실제 처리 결과를 확인한 뒤 정해요.

### F-02 · 진행 상태와 실패 복구

- **상태**: `대기 중 → 요약 중 → 완료` 또는 `실패`로 구분해요.
- **행동**: 사용자는 진행 상태를 확인하거나 다른 화면으로 이동할 수 있어요. 앱으로 돌아오거나 앱을 다시 열어도 같은 계정의 요청 상태를 확인해요.
- **실패**: 입력 오류는 URL 수정, 일시적 처리 오류는 재시도, 상태 조회 오류는 상태 다시 확인으로 연결해요.
- **표시 원칙**: 근거 없는 완료 시간이나 진행률을 보여주지 않아요. 완료하지 못한 작업을 성공으로 표시하지 않아요.
- **수용 기준 AC-02**: 앱 재진입과 화면 회전이 새 분석을 만들지 않고, 조회 재시도와 분석 재시도를 구분해요.

### F-03 · 리포트 생성과 읽기

- **기본 구성**: 제목·채널명·원본 링크, 세 줄 요약, 주제별 본문, 핵심 정리, 생각해볼 질문이에요.
- **읽기 도구**: 목차와 중요한 장면의 시간 링크를 제공해요. 리포트가 AI로 작성됐다는 점을 알려줘요.
- **품질**: 영상에 없는 주장이나 수치를 만들지 않고 핵심 맥락을 유지하는 것을 목표로 해요. 분량은 내용에 맞춰요.
- **결과**: 완성한 글을 저장한 뒤 읽기 화면과 보관함에서 제공해요.
- **수용 기준 AC-03**: 본문을 읽고 원본을 열 수 있어요. 품질 평가는 표본 영상의 실제 내용과 리포트를 대조해 확인해요.

시간 링크가 존재하는지만 검사해서 정확하다고 판단하지 않아요. 근거 시점을 확인할 수 없는 내용에는 추측한 시간 링크를 붙이지 않는 방향이에요.

### F-04 · 보관함과 탐색

- **입력**: 제목 검색어, 채널, 생성 경로, 발송 상태 필터예요.
- **결과**: 최신 생성순 목록에서 리포트를 고르고 본문을 열어요. 생성 경로는 `직접 요약`과 `채널 자동`으로 구분해요.
- **빈 상태**: 아직 결과가 없는 경우와 검색 조건에 맞지 않는 경우를 구분해요.
- **수용 기준 AC-04**: 저장된 글을 다시 읽을 때 새 분석을 하지 않고, 채널을 삭제해도 기존 글을 찾을 수 있어요.

### F-05 · 채널 관리

- **입력**: 채널 주소 또는 `@핸들`이에요.
- **행동**: 검색 결과의 채널명·주소를 확인한 뒤 `채널 등록`을 눌러요. 같은 채널은 중복 등록하지 않아요.
- **변경**: 자동 요약을 일시 중지하거나 다시 켤 수 있어요. 삭제 전에는 중단되는 항목과 리포트 보존을 안내해요.
- **수용 기준 AC-05**: 중지·삭제한 채널의 신규 확인과 대기 메일 재시도가 멈추고, 완성된 리포트는 유지돼요.

### F-06 · 새 영상 자동 확인

- **시작**: 활성 채널과 수신 설정을 갖춘 뒤 예약된 주기 또는 `지금 확인`으로 시작해요.
- **첫 확인**: 현재 채널의 영상 목록을 시작 기준으로 삼고 과거 영상을 일괄 요약하지 않아요. 이 정책을 등록 단계에서 알려줘요.
- **반복 확인**: 이후 새로 발견한 영상의 리포트를 만들어요. 이미 저장된 결과나 진행 요청이 있으면 중복 생성하지 않아요.
- **예외**: 첫 확인에 실패하면 시작 기준이 아직 정해지지 않았음을 알려줘요. 개별 영상 실패와 채널 확인 완료는 구별해요.
- **수용 기준 AC-06**: 첫 확인은 과거 영상 대량 생성을 일으키지 않고, 다음 확인에서 새로 발견한 영상만 처리해요. 빈 채널도 첫 확인 완료 여부를 기록해 첫 업로드를 반복해서 제외하지 않아요.

확인 주기는 도착 보장 시간이 아니에요. 채널 제공 정보의 지연이나 장기간 중지로 영상을 놓칠 수 있어요. 원하는 과거 영상은 직접 URL로 요청할 수 있어요.

### F-07 · 이메일 전달과 재시도

- **대상**: 채널 자동 요약으로 완성한 리포트예요. 직접 요약은 `발송 안 함`으로 구분해요.
- **내용**: 영상 제목·채널명, 리포트 본문, 원본 링크를 포함해요. 영상마다 한 통을 보내는 방식이에요.
- **실패 복구**: 리포트는 유지하고 발송만 재시도해요. 메일 문제 때문에 영상을 다시 분석하지 않아요.
- **중단 조건**: 채널이 중지·삭제되거나 수신 설정이 유효하지 않으면 해당 자동 발송을 멈춰요. 재시도 횟수·간격은 운영 정책으로 정해요.
- **수용 기준 AC-07**: 메일 실패 후에도 글을 읽을 수 있고, 발송 재시도가 새 리포트를 만들지 않아요. 이미 성공한 수신 주소에 대한 중복 발송을 방지해요.

발송 완료는 수신자가 읽었다는 뜻이 아니에요. 직접 만든 결과는 이후 같은 채널을 등록해도 자동으로 소급 발송하지 않아요.

### F-08 · 수신 설정과 확인 주기

- **입력**: 수신 이메일 주소와 채널 확인 주기예요.
- **행동**: 주소를 추가·삭제하고, 사람이 이해할 수 있는 주기 옵션을 선택해 저장해요. 시간 기준이 필요한 옵션은 시간대를 함께 표시해요.
- **검증**: 잘못된 주소와 중복 주소를 안내해요. 저장 실패 시 입력값을 유지해 다시 시도할 수 있게 해요.
- **수용 기준 AC-08**: 적용된 수신 주소·주기를 확인할 수 있어요. 수신 설정이 없어도 직접 URL 요약은 이용할 수 있어요.

### F-09 · 홈에서 현황 보기

- **표시**: 최근 리포트, 활성 채널 수, 진행 중인 요약, 발송 대기·실패, 마지막 확인과 다음 예정이에요.
- **행동**: 최근 결과를 열거나 `지금 확인`으로 등록 채널을 확인해요.
- **수용 기준 AC-09**: 직접 요약의 `발송 안 함`을 실패나 발송 대기로 집계하지 않아요. 처리 상태를 보고 다음 행동을 선택할 수 있어요.

### F-10 · Android 사용 경험과 접근성

- **화면**: 스마트폰 세로 화면을 기본으로 목록과 본문을 한 번에 하나씩 보여줘요. 목록 복귀와 원본 이동을 쉽게 제공해요.
- **조작**: Android 뒤로 가기는 상세에서 이전 목록으로 돌아가고, 입력 중에는 키보드를 먼저 닫아요. 입력 레이블, 키보드 탐색, 색 이외의 상태 텍스트를 제공해요. 라이트·다크 테마를 선택할 수 있어요.
- **수용 기준 AC-10**: 모바일에서 URL 입력부터 본문 읽기·목록 복귀까지 할 수 있어요. 상태 변화는 화면을 읽어주는 TalkBack 같은 보조기기로도 알 수 있어야 해요. 네트워크가 끊기면 연결 상태와 다시 시도할 행동을 알려줘요.

### F-11 · Google 로그인과 사용자별 기록

- **시작**: 앱을 처음 열면 제품 설명과 `Google로 계속하기`를 보여줘요. 로그인 성공 후 영상 요약 화면으로 이동해요.
- **계정 선택**: Google 계정 선택 화면을 사용해요. 처음 로그인한 계정은 별도 비밀번호 가입 없이 앱 사용을 시작하는 흐름이에요.
- **취소·실패**: 계정 선택 취소는 로그인 화면으로 돌아가고 오류로 몰아붙이지 않아요. 연결 실패는 이유와 재시도 버튼을 제공해요.
- **로그인 유지**: 유효한 로그인 상태가 있으면 다시 계정을 선택하지 않아요. 만료 등으로 재인증이 필요하면 로그인으로 안내하고 의도한 화면으로 복귀해요.
- **기록 분리**: 보관함·채널·수신 설정·진행 요청은 사용자별로 분리해요. 공유 보관함은 첫 범위에 포함하지 않아요. 화면뿐 아니라 데이터 접근 단계에서도 소유자를 확인해야 해요.
- **로그아웃**: 설정에서 로그아웃하면 개인 화면과 기기의 이전 계정 표시·캐시를 비우고 로그인 화면으로 이동해요. 서버의 리포트는 지우지 않아요.
- **자동화와 관계**: 로그아웃은 채널 구독 취소가 아니에요. 진행 요청과 설정한 자동 요약은 계속될 수 있음을 안내하고, 멈추려면 채널을 중지하도록 해요.
- **수용 기준 AC-11**: 로그인 성공·취소·실패·로그아웃이 구분돼요. A 계정으로 만든 기록이 B 계정의 목록·검색·상세 조회에 나타나지 않아요. 같은 계정으로 다시 로그인하면 저장한 결과를 볼 수 있어요.

인증 방식 후보는 Google 로그인과 Firebase Authentication의 조합이에요. Android의 Credential Manager로 계정 선택을 연결하는 공식 흐름을 참고해요. [공식 연동 문서](https://firebase.google.com/docs/auth/android/google-signin)

## 3. 요약 상태와 메일 상태

| 종류 | 상태 | 사용자에게 의미하는 것 |
| --- | --- | --- |
| 요약 | 대기 중 | 요청을 받았고 처리를 기다려요. |
| 요약 | 요약 중 | 영상 내용을 정리하고 있어요. |
| 요약 | 완료 | 리포트가 저장돼 읽을 수 있어요. |
| 요약 | 실패 | 결과를 완성하지 못했어요. 이유와 다음 행동을 안내해요. |
| 메일 | 발송 안 함 | 직접 요청한 결과라 이메일 대상이 아니에요. |
| 메일 | 발송 대기 | 결과는 있고 이메일 전달을 기다려요. |
| 메일 | 발송됨 | 발송이 완료됐어요. 열람 확인은 아니에요. |
| 메일 | 발송 실패 | 결과는 있지만 이메일 전달에 문제가 있어요. |

예를 들어 `요약 완료 / 발송 실패`는 글을 바로 읽을 수 있는 상태예요. 분석 실패와 이메일 실패를 하나의 오류로 묶지 않아요.

## 4. 팀 검토 시나리오

| 상황 | 기대 경험 | 연결 기능 |
| --- | --- | --- |
| 로그인에서 Google 계정 선택을 취소해요. | 로그인 화면에 남고 다시 시작할 수 있어요. | F-11 |
| A 계정에서 로그아웃한 뒤 B 계정으로 들어가요. | A 계정의 보관함·채널·상태가 노출되지 않아요. | F-11 |
| 로그인 후 영상 링크 하나를 입력해요. | 채널·메일 설정 없이 리포트에 도달해요. | F-01~03 |
