# Qletter PRD — 제품 요구사항

> **Qletter(큐레터)는 YouTube 영상을 읽기 쉬운 한국어 리포트로 바꿔주는 안드로이드 AI 앱이에요.**
> 영상 링크를 넣어 한 편을 요약하거나, 관심 채널을 등록해 새 영상의 리포트를 받아볼 수 있어요.

이 문서 묶음은 **숭실대학교 사용자인터페이스 전공 과목 팀프로젝트**를 위한 기획 초안이에요. 목표는 로그인부터 요약 요청·읽기·보관까지 이어지는 안드로이드 앱을 만드는 것이에요. 아래 내용은 제안하는 사용 경험이며, 현재 제공 중인 기능 목록을 뜻하지 않아요.

| 프로젝트 기준 | 내용 |
| --- | --- |
| 결과물 | 안드로이드 앱 |
| 필수 진입 기능 | 이메일·비밀번호 회원가입과 로그인 |
| 핵심 시연 | 로그인 → 영상 URL 입력 → 요약 → 리포트 읽기 → 내 보관함에서 다시 찾기 |
| 설계 초점 | 처음 사용하는 사람도 이해하는 화면, 일관된 이동, 대기·오류 피드백, 접근성 |

## 1. 해결하려는 문제

관심 있는 영상은 많지만 모두 시청할 시간은 부족해요. 긴 영상의 핵심만 알고 싶어도 재생 구간을 옮겨가며 찾아야 하고, 나중에 다시 확인하려면 같은 과정을 반복해요. 자주 보는 채널의 새 영상을 챙기는 일도 번거로워요.

Qletter는 이 과정을 세 가지로 줄여요.

1. **선택하기**: 영상 링크를 넣거나 관심 채널을 등록해요.
2. **이해하기**: 세 줄 요약으로 핵심을 훑고, 필요한 부분은 본문으로 읽어요.
3. **다시 찾기**: 리포트를 보관하고 원본 영상의 해당 장면으로 돌아가요.

예를 들어, 공유받은 40분짜리 강연의 링크를 넣으면 핵심 주장과 설명을 글로 읽을 수 있어요. 더 궁금한 내용은 본문의 시간 링크를 눌러 원본에서 확인해요. 이 예시는 사용 상황을 설명하기 위한 것이며 특정 처리 시간이나 정확도를 보장하지 않아요.

## 2. 누구를 위한 제품인가요?

| 사용자 | 겪는 문제 | 원하는 결과 |
| --- | --- | --- |
| 바쁜 직장인 | 업무와 관련된 긴 영상을 모두 보기 어려워요. | 핵심을 먼저 파악하고 볼 부분을 골라요. |
| 학생·학습자 | 강의나 설명 영상의 내용을 복습하기 어려워요. | 구조화된 글과 원본 장면으로 다시 공부해요. |
| 지식 콘텐츠 구독자 | 여러 채널의 새 영상을 계속 확인해야 해요. | 관심 채널의 내용을 자동으로 받아봐요. |
| 특정 영상이 궁금한 사람 | 공유받은 영상 한 편의 내용만 알고 싶어요. | 복잡한 설정 없이 링크로 시작해요. |

이 구분은 사용자 가설이에요. 실제 수요와 중요도는 인터뷰와 사용성 평가로 확인해요.

## 3. 두 가지 핵심 사용 방식

| 구분 | 영상 직접 요약 | 채널 자동 요약 |
| --- | --- | --- |
| 시작 | YouTube 영상 URL 하나 입력 | 채널 주소 또는 핸들 등록 |
| 목적 | 지금 궁금한 한 편을 읽어요. | 앞으로 올라올 새 영상을 꾸준히 받아봐요. |
| 결과 | 리포트 화면과 보관함 | 리포트 화면·보관함·이메일 |
| 이메일 | 자동으로 보내지 않아요. | 등록한 수신 주소로 보내요. |
| 채널 등록 | 필요하지 않아요. | 필요해요. |

두 방식은 같은 리포트 형식과 보관함을 사용해요. 영상 한 편을 요청했다고 그 채널을 자동 구독하거나 이메일 수신을 시작하지 않아요.

## 4. 리포트는 어떤 결과물인가요?

리포트는 **영상 한 편의 핵심과 맥락을 정리한 글**이에요.

- 영상 제목·채널명·원본 링크로 출처를 알려줘요.
- 세 줄 요약으로 핵심을 먼저 보여줘요.
- 주요 주제별 설명으로 주장·사례·수치의 맥락을 풀어줘요.
- 중요한 장면의 시간 링크로 원본 확인을 도와요.
- 마무리에는 핵심 정리와 생각해볼 질문을 담아요.

글의 길이는 내용에 맞추고, 분량을 채우기 위해 설명을 반복하지 않아요. AI가 만든 해석이므로 중요한 정보는 원본을 확인할 수 있게 해요.

## 5. 첫 출시 범위

**필수**는 제품의 핵심 가치를 전달하는 기능, **보조**는 사용 편의를 높이는 기능이에요.

| 우선순위 | 기능 | 사용자 가치 | 기능 번호 |
| --- | --- | --- | --- |
| 필수 | 이메일·비밀번호 회원가입·로그인·로그아웃·개인 보관함 | 내 계정으로 결과를 저장하고 다시 읽어요. | F-11 |
| 필수 | URL 입력과 영상 한 편 요약 | 채널 등록 없이 바로 시작해요. | F-01 |
| 필수 | 요청 진행 상태·실패 안내·재시도 | 기다릴지 다시 시도할지 판단해요. | F-02 |
| 필수 | 한국어 리포트와 원본 시간 링크 | 핵심을 이해하고 근거를 확인해요. | F-03 |
| 필수 | 보관함·제목 검색·필터 | 이전에 읽은 내용을 다시 찾아요. | F-04 |
| 필수 | 채널 등록·일시 중지·삭제 | 관심 채널을 관리해요. | F-05 |
| 필수 | 새 영상 자동 확인 | 반복해서 링크를 넣지 않아도 돼요. | F-06 |
| 필수 | 이메일 전달과 발송 실패 복구 | 일상에서 리포트를 받아봐요. | F-07 |
| 필수 | 수신 주소와 확인 주기 설정 | 자동화 방식을 이해하고 조절해요. | F-08 |
| 보조 | 최근 리포트·진행 현황 요약 | 처리 결과를 한눈에 확인해요. | F-09 |
| 필수 | Android 화면 이동·접근성·상태 복원 | 뒤로 가기와 앱 재진입에서도 자연스럽게 이어져요. | F-10 |
| 보조 | 화면 테마 | 편한 밝기로 읽어요. | F-10 |

프로젝트는 먼저 로그인·직접 요약·리포트·내 보관함을 연결해 시연하고, 이어서 채널 자동 요약과 이메일을 완성하는 순서로 제안해요. 전체 기획 범위는 위 표와 같아요.

첫 버전에서는 재생목록 일괄 요약, 파일 업로드, 영상과의 AI 채팅, 번역 언어 선택, 팀 공동 편집, 외부 문서 도구로 내보내기를 다루지 않아요. 이메일은 영상별 리포트이며 여러 영상을 합친 일간 뉴스레터는 별도 아이디어로 남겨요.

## 6. 중요한 제품 규칙

1. **한 편으로 시작할 수 있어요.** 직접 요약에 채널 등록이나 이메일 설정을 요구하지 않아요.
2. **같은 영상을 불필요하게 다시 분석하지 않아요.** 같은 계정의 기존 결과나 진행 요청이 있으면 재사용해요.
3. **처음 등록한 채널의 과거 영상을 한꺼번에 처리하지 않아요.** 첫 확인에서 시작 기준을 정하고 이후 새로 발견한 영상을 처리해요. 원하는 과거 영상은 URL로 요청해요.
4. **리포트를 먼저 보관해요.** 이메일이 실패해도 앱에서 읽을 수 있어요.
5. **직접 요청한 결과를 자동 메일로 바꾸지 않아요.** 이후 같은 채널을 등록해도 이미 만든 직접 요약을 소급 발송하지 않아요.
6. **채널 삭제와 리포트 삭제를 구분해요.** 채널을 지워도 기존 리포트는 남아요.
7. **자동화의 한계를 설명해요.** 확인 주기는 영상이 반드시 도착하는 시한이 아니고, 장기간 중지한 동안의 모든 영상을 복구한다고 약속하지 않아요.
8. **내 기록은 내 계정에서만 보여요.** 로그인한 사용자의 리포트·채널·수신 설정을 구분하고, 계정을 바꾸면 이전 사용자의 기록이 보이지 않게 해요.

## 7. 성공을 어떻게 판단하나요?

사용자의 핵심 이해와 반복 사용을 중심으로 평가해요. 아래 항목은 측정 계획이며 성과 수치가 아니에요.

| 지표 | 확인할 질문 | 측정 방법 |
| --- | --- | --- |
| 가입·로그인 완료 | 회원가입과 로그인, 입력 오류 수정, 실패 후 다시 시도하기가 이해되나요? | Android 기기에서 회원가입·첫 로그인·재로그인을 관찰해요. |
| 첫 요약 완료율 | 처음 온 사람이 로그인 후 리포트까지 도달하나요? | 유효한 URL 요청 중 결과 열람에 도달한 비율을 봐요. |
| 이해에 걸린 시간 | 글이 핵심을 파악하는 데 도움이 되나요? | 원본 시청과 리포트 읽기 후 같은 질문에 답하게 해요. |
| 요약 품질 | 주요 주장과 설명이 원본에 충실한가요? | 표본 리포트를 원본과 대조해 오류·누락을 기록해요. |
| 원본 연결 품질 | 시간 링크가 관련 장면으로 이어지나요? | 핵심 주장과 연결된 장면을 직접 확인해요. |
| 반복 사용 | 다음 영상도 이 방식으로 읽고 싶나요? | 재사용 기록과 사용자 인터뷰를 함께 봐요. |
| 자동 전달 안정성 | 새 영상의 결과를 꾸준히 받아볼 수 있나요? | 영상 발견·요약·발송 단계별 성공과 실패를 구분해요. |

목표 수치는 초기 사용성 평가와 처리 비용을 확인한 뒤 정해요. 이메일 발송 성공과 실제 수신·열람은 따로 측정해요.

## 8. 팀에서 결정할 사항

| 항목 | 결정이 필요한 이유 |
| --- | --- |
| 핵심 사용자와 콘텐츠 분야 | 강의·뉴스·리뷰 등에 따라 좋은 요약의 기준이 달라요. |
| 지원 Android 버전 | Android Studio 기반으로 개발하고, 지원 버전은 수업용 기기 조건에 맞춰 정해야 해요. |
| 요약 가능한 영상과 길이 | 접근 가능성·품질·처리 비용을 함께 확인해야 해요. |
| 무료 사용량·요금 정책 | 실제 비용과 재사용 효과를 측정한 뒤 정해야 해요. |
| 기본 확인 주기와 실패 재시도 한도 | 사용자의 기대와 운영 비용 사이의 기준이 필요해요. |
| 정보 보관·삭제 정책 | 사용자가 자신의 리포트와 수신 정보를 관리할 수 있어야 해요. |
| 이메일 확인·비밀번호 재설정 정책 | 계정 소유 확인과 비밀번호를 잊은 사용자의 복구 흐름을 인증 기능 구현 전에 정해야 해요. |

## 9. 로그인 방식

**이메일과 비밀번호를 사용하는 일반 로그인**으로 정했어요. 처음 사용하는 사람은 회원가입으로 Qletter 계정을 만들고, 기존 사용자는 로그인해 자신의 기록을 이어서 이용해요.

로그인 화면에는 이메일·비밀번호 입력과 `로그인`, `회원가입`을 제공해요. 회원가입 화면에서는 이메일·비밀번호·비밀번호 확인을 입력해요. 가입 완료 후 로그인 화면으로 돌아가고, 로그인에 성공하면 영상 요약 화면으로 이동해요. 유효한 로그인 상태가 있으면 반복 입력을 요구하지 않아요.

로그인 이메일과 리포트 수신 주소는 별개예요. 계정을 만들거나 로그인했다고 채널 자동 요약이나 이메일 발송을 켜지 않아요. YouTube 구독 목록이나 Gmail 접근 권한을 요구하지 않아요.

인증의 저장·세션·이메일 확인·비밀번호 재설정 방식은 인증 기능 구현 전에 구체화해요. 현재 [모노레포 초기 구성](06-development-setup-design.md)은 협업 환경과 서버·앱 기본 연결까지이며 인증 기능 구현을 포함하지 않아요.
